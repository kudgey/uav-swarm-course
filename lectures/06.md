# Модуль 06 · Багатоагентне навчання: моделі та виклики

Два дрони летять назустріч вузьким коридором, і розминутися можна лише в одному місці: що робити кожному, залежить від іншого. Лекція будує мову для таких задач і показує на справжніх прогонах, чому вчитися поруч з іншим агентом складніше, ніж наодинці.

Схема багатоагентного навчання з підкріпленням: $n$ агентів отримують спостереження й винагороди (*observation & reward*), їхні дії (*action*) складаються у спільну дію (*joint action*), яка змінює стан середовища (*environment*).

### Зміст лекції

Багатоагентне навчання з підкріпленням (*multi-agent reinforcement learning*, MARL) має дві складові. **Модель гри** описує, хто що бачить, які дії доступні й від чого залежить винагорода. **Концепція розв'язку** каже, яку спільну поведінку вважати доброю. Усю лекцію тримаємося однієї задачі — два дрони в коридорі з кишенею.

Частина 1 будує на коридорі чотири моделі ігор. Частина 2 розбирає п'ять матричних ігор і шукає в них рівноваги кодом. Частина 3 дає означення: очікувана віддача, найкраща відповідь, рівновага Неша, мінімакс, Парето, добробут і справедливість. Частина 4 порівнює одну таблицю на двох і в кожного свою на прогоні в коридорі. Частина 5 показує на даних чотири виклики MARL.

### Результати навчання

Після лекції ви зможете:

- записати кортежем гру в нормальній формі, стохастичну гру й частково спостережувану стохастичну гру (POSG) та показати кожну на задачі коридору;
- знайти детерміновані рівноваги Неша в матричній грі, а для гри 2 × 2 — і ймовірнісну, з умови байдужості;
- порахувати очікувану віддачу ймовірнісної спільної політики, найкращу відповідь, Парето-оптимальні клітинки, добробут і справедливість;
- пояснити, чим централізоване навчання відрізняється від незалежного, і прочитати їхні криві на одній задачі;
- показати на числах нестаціонарність і те, до якої рівноваги сходиться незалежне Q-навчання в Stag Hunt;
- порахувати різницеві винагороди для спільної задачі й оцінити, як росте простір спільних дій із числом агентів.

### Наскрізна задача: два дрони в коридорі

Два апарати обстежують тунель і мають помінятися кінцями: синій летить зліва направо, помаранчевий — справа наліво. Тунель вузький, розминутися можна лише через **кишеню** — нішу над середньою клітинкою.


<Figure src="/figs/own/mod06-corridor.png" msrc="/figs/own/mod06-corridor-m.png" alt="Коридор із п'яти клітинок 0–4 і кишенею K над клітинкою 2. Поруч правила: дії вперед, чекати, кишеня; −1 за крок кожного дрона, −50 за зіткнення, винагорода спільна">

Коридор із п'яти клітинок 0–4 і кишенею K над клітинкою 2. Синій дрон у клітинці 0 летить праворуч до виходу, помаранчевий у клітинці 4 — ліворуч. Блакитна смуга над клітинками 0–1 — що бачить сенсор синього з радіусом 1. Поруч правила: дії вперед, чекати, кишеня; −1 за крок кожного дрона, −50 за зіткнення, винагорода спільна

</Figure>


Модель навмисно мала, щоб усі числа можна було перевірити:

- ряд із п'яти клітинок 0–4 і кишеня K над клітинкою 2; синій стартує в 0 і вилітає праворуч за 4, помаранчевий — навпаки;
- кожен крок обидва **одночасно** обирають «вперед», «чекати» або «кишеня»: у клітинці 2 — пірнути в кишеню, з кишені «вперед» повертає в клітинку 2, а деінде «кишеня» — те саме, що «чекати»;
- якщо обидва опиняються в одній клітинці або міняються клітинками, — зіткнення, і політ закінчується;
- винагорода **спільна**, одна на двох: −1 за кожен крок кожного дрона в коридорі і −50 за зіткнення.

«Вперед» для синього добре, якщо помаранчевий у цей момент чекає, і погано, якщо він теж летить уперед. Наслідок дії залежить від **спільної дії** — пари дій обох агентів. Саме цієї залежності не було в модулях 04–05, де агент був один.

### Один крок: що бачить кожен дрон

Код нижче — увесь коридор: функція `step` за станом і спільною дією повертає новий стан, винагороду й ознаку кінця, а `see` — те, що бачить сенсор дрона. Сенсор має радіус 1: дрон бачить інший апарат, лише якщо той у сусідній клітинці. Стан — пара місць (синій, помаранчевий); 5 означає кишеню, 6 — «вже вилетів».


<CodeFold title="Коридор: два дрони, один крок і що бачить кожен" :lines="48" sec="0.0">

```python
import itertools

K, HOME = 5, 6  # клітинки ряду 0–4, кишеня над клітинкою 2, «вилетів»
DIR, START = (+1, -1), (0, 4)  # синій летить праворуч, помаранчевий — ліворуч
ACTS = ("вперед", "чекати", "кишеня")
STEP_COST, CRASH = -1.0, -50.0  # за крок кожного дрона в коридорі; за зіткнення
JOINT = list(itertools.product(range(3), repeat=2))  # 9 спільних дій


def move(i, p, a):
    """Нове місце дрона i з місця p після дії a, без перевірки зіткнень."""
    if p == HOME:
        return HOME
    if p == K:
        return 2 if a == 0 else K  # «вперед» з кишені — назад у клітинку 2
    if a == 0:
        q = p + DIR[i]
        return HOME if q < 0 or q > 4 else q
    return K if a == 2 and p == 2 else p  # «кишеня» деінде — те саме, що чекати


def step(s, a):
    """Спільний крок: стан (p0, p1), спільна дія (a0, a1) → (s′, r, кінець)."""
    new = (move(0, s[0], a[0]), move(1, s[1], a[1]))
    flying = sum(p != HOME for p in s)
    same = new[0] == new[1] != HOME
    swap = new[0] == s[1] != HOME and new[1] == s[0] != HOME
    if same or swap:
        return new, CRASH, True
    return new, STEP_COST * flying, new == (HOME, HOME)


def see(i, s, radius=1):
    """Спостереження дрона i: своє місце і чуже, лише якщо воно ближче за radius."""
    x = [2 if p == K else p for p in s]  # кишеня — над клітинкою 2
    near = HOME not in s and abs(x[0] - x[1]) <= radius
    return (s[i], s[1 - i] if near else "не видно")


STATES = [
    s for s in itertools.product(range(7), repeat=2) if s[0] != s[1] or s[0] == HOME
]
print(f"станів {len(STATES)}, дій у дрона {len(ACTS)}, спільних дій {len(JOINT)}")
s, a = (1, 3), (0, 1)
s2, r, done = step(s, a)
print("стан  спостереження синього / помаранчевого   дії            → стан  r")
print(f"{s}  {see(0, s)} / {see(1, s)}   {ACTS[a[0]]}/{ACTS[a[1]]} → {s2}  {r:+.0f}")
print(f"{s2}  {see(0, s2)} / {see(1, s2)}")
```

Так виглядають дані, з якими працюватимуть усі алгоритми лекції: у стані (1, 3) дрони не бачать один одного, синій полетів уперед, помаранчевий чекав, винагорода −1 − 1 = −2, і після кроку вони вже сусіди. Стан знає симулятор, а кожен дрон — лише своє спостереження. Що доступно агентові і чи винагорода в нього своя, визначає модель гри — частина 1 будує їх по черзі.

## Частина 1 · Моделі ігор

Модель гри описує механіку взаємодії. Моделі цієї частини пов'язані відношенням «окремий випадок», і всі вони видно на коридорі.


<Figure src="/figs/ext/m05-game-hierarchy.png" alt="Ієрархія моделей ігор: POSG, стохастична гра, повторювана гра, MDP">

Джерело: [Albrecht, Christianos, Schäfer, 2024](https://www.marl-book.com/), рис. 3.1. Ієрархія моделей: частково спостережувана стохастична гра (*Partially Observable Stochastic Game*: $n$ агентів, $m$ станів, спостерігаються частково) містить стохастичну гру (*Stochastic Game*: стани спостерігаються повністю), а та — повторювану гру в нормальній формі (*Repeated Normal-Form Game*: $n$ агентів, 1 стан) і марковський процес прийняття рішень (*Markov Decision Process*: 1 агент, $m$ станів).

</Figure>


На коридорі: одна зустріч біля кишені — гра в нормальній формі (якщо повторюється — повторювана гра з рисунка); увесь політ — стохастична гра; політ, коли кожен бачить лише сусідню клітинку, — частково спостережувана стохастична гра (POSG), а з однією винагородою на двох — Dec-POMDP (обидві означено нижче). Якщо дрон один, лишається MDP з модуля 04.

### Гра в нормальній формі: одна зустріч

Найпростіша модель — одна одночасна взаємодія без станів.

$$\Gamma = \big(I,\ \{A_i\}_{i\in I},\ \{R_i\}_{i\in I}\big), \qquad A = A_1\times\dots\times A_n, \qquad R_i : A\to\mathbb{R}$$

| **Позначення** | **Значення** |
|---|---|
| $I=\{1,\dots,n\}$ | множина агентів; у коридорі $n = 2$ |
| $A_i$ | множина дій агента $i$ |
| $a = (a_1,\dots,a_n) \in A$ | спільна дія — по одній дії кожного агента |
| $R_i(a)$ | винагорода агента $i$ за спільну дію $a$ |

Підручник Albrecht et al. (рис. 4.3) описує таку зустріч грою «хто зверне» (*Chicken*): S (*straight*) — не звертати, L (*leave*) — звернути. Рядок — дія агента 1, стовпець — агента 2, у клітинці — $r_1, r_2$.

| **агент 1 \ агент 2** | **S** | **L** |
|---|---|---|
| **S** | 0, 0 | 7, 2 |
| **L** | 2, 7 | 6, 6 |

Числа тут — умовні бали з підручника, а не час польоту: 7 — пройшов першим, 2 — поступився, 6 — обидва звернули й розминулися повільніше, 0 — зіткнення. Наприклад, $R_1(S, L) = 7$, $R_2(S, L) = 2$: агент 1 не звернув, агент 2 звернув. Власні числа коридору, пораховані кодом, — нижче, у стохастичній грі.

Якщо ту саму гру повторювати, отримуємо **повторювану гру** (*repeated game*): політика тепер може залежати від історії попередніх спільних дій.

### Стохастична гра: у кожному стані своя матриця

Політ коридором — це не одна зустріч, а низка кроків, і після кожного стан змінюється. **Стохастична гра** додає до нормальної форми стани й переходи між ними.

$$G = \big(I,\ S,\ \{A_i\},\ \{R_i\},\ T,\ \mu\big), \qquad T(s'\mid s,a) = \Pr(s^{t+1}=s'\mid s^t=s,\ a^t=a)$$

| **Позначення** | **Значення** | **У коридорі** |
|---|---|---|
| $S$ | множина станів | 43 пари місць (синій, помаранчевий) |
| $T(s'\mid s,a)$ | імовірність потрапити в $s'$ зі стану $s$ після спільної дії $a$ | 1 або 0: коридор детермінований |
| $\mu(s)$ | імовірність почати в стані $s$ | $\mu\big((0,4)\big) = 1$ |
| $R_i(s,a,s')$ | винагорода агента $i$ — тепер залежить і від стану, і від переходу | −1 за кожен дрон у коридорі, −50 за зіткнення |

Кожен стан стохастичної гри можна читати як окрему матричну гру. Для спільної винагороди її «виплата» за спільну дію — винагорода цього кроку плюс найкраща віддача з наступного стану: $Q^*(s,a) = r + V^*(s')$, де $V^*(s')$ — найбільша спільна віддача, якої можна досягти зі стану $s'$. Її рахує динамічне програмування з модуля 04 — прохід за проходом за рівнянням Беллмана (*value iteration*), лише над дев'ятьма спільними діями.


*Продовження блоку «Коридор: два дрони, один крок і що бачить кожен»: цей код виконується разом із ним.*

<CodeFold title="Коридор як стохастична гра: оптимум і матриця одного стану" :lines="35" sec="0.1">

```python
# продовження блоку «Коридор: два дрони»
def solve(allowed):
    """Ітерація за цінністю для спільної винагороди (γ = 1) на дозволених діях."""
    V = {s: 0.0 for s in STATES}
    for _ in range(50):
        for s in STATES:
            if s != (HOME, HOME):
                V[s] = max(q(V, s, a) for a in allowed)
    return V


def q(V, s, a):
    """Цінність спільної дії a в стані s, якщо далі обидва діють найкраще."""
    s2, r, d = step(s, a)
    return r + (0 if d else V[s2])


V = solve(JOINT)
print(f"найкраща спільна віддача зі старту {START}: {V[START]:+.0f}")
for who, other in (("синій", 1), ("помаранчевий", 0)):
    allowed = [a for a in JOINT if a[other] != 2]  # другому кишеня заборонена
    W, s, path = solve(allowed), START, []
    while s != (HOME, HOME):
        a = max(allowed, key=lambda a: q(W, s, a))
        path.append(f"{ACTS[a[0]][:3]}/{ACTS[a[1]][:3]}")
        s = step(s, a)[0]
    print(
        f"пірнає {who}: віддача {W[START]:+.0f}, {len(path)} кроків: " + ", ".join(path)
    )
s = (1, 3)
print(f"стан {s}: Q*(a0, a1) = r + V*(s′); рядок — синій, стовпець — помаранчевий")
for a0 in range(3):
    print(
        f"{ACTS[a0]:>7s} " + " ".join(f"{q(V, s, (a0, a1)):+5.0f}" for a1 in range(3))
    )
```

Оптимум — 7 кроків і −13, і в кишеню може пірнути будь-хто з двох. У матриці стану (1, 3) клітинок −11 чотири, але варіантів по суті два: уперед летить **рівно один** дрон, синій або помаранчевий («кишеня» тут — те саме, що «чекати»). Обидва вперед — −50, обидва чекають — −13. Винагорода спільна, тож це гра координації: дрони хочуть одного, але не знають, хто поступиться. Якби кожен рахував лише свій час, матриця стала б схожою на «хто зверне».

### POSG і Dec-POMDP: сенсор бачить не все

Справжній дрон бачить лише те, що ловить його сенсор. **Частково спостережувана стохастична гра** (*partially observable stochastic game*, POSG) — та сама стохастична гра, у якій агент замість стану отримує спостереження.

$$\big(I,\ S,\ \{A_i\},\ \{O_i\},\ \{\Omega_i\},\ \{R_i\},\ T,\ \mu\big), \qquad \Omega_i(o_i\mid a, s')$$

| **Позначення** | **Значення** | **У коридорі** |
|---|---|---|
| $O_i$ | множина спостережень агента $i$ | (своє місце, місце іншого або «не видно») |
| $\Omega_i(o_i\mid a,s')$ | імовірність отримати спостереження $o_i$, якщо спільна дія $a$ привела в стан $s'$ | 1 для того, що реально бачить сенсор із радіусом 1 |

Решта символів — як у стохастичній грі. Оскільки стан невідомий, політика агента залежить від історії його спостережень: $\pi_i(a_i\mid h_i^t)$, де $h_i^t = (o_i^0,\dots,o_i^t)$. Агент може тримати **стан переконань** (*belief state*) — розподіл імовірностей того, де зараз інший дрон; оновлювати його — та сама задача, що у фільтрі Калмана з модуля 02. Точне оновлення дороге, тож у глибокому MARL історію подають **рекурентній мережі** — мережі з пам'яттю (модуль 09).


<Figure src="/figs/ext/m05-partial-observability.png" alt="Середовище level-based foraging із частковою спостережуваністю">

Джерело: [Albrecht, Christianos, Schäfer, 2024](https://www.marl-book.com/), рис. 3.4. Збирання ресурсів за рівнями (*level-based foraging*, LBF) — стандартне середовище книги: агенти й предмети мають рівні (числа поруч), а з частковою спостережуваністю кожен агент бачить лише сіру область навколо себе.

</Figure>


Окремий випадок POSG має власну назву. POMDP (*partially observable Markov decision process*) — частково спостережуваний MDP: один агент бачить спостереження, а не стан. Якщо агентів кілька, а винагорода спільна, $R_1 = \dots = R_n$, це **децентралізований POMDP** (*decentralized POMDP*, Dec-POMDP). Коридор зі спільною винагородою й сенсором — саме Dec-POMDP, як і більшість задач рою.

## Частина 2 · Матричні ігри

Матрична гра — гра в нормальній формі з таблицею виплат: рядок — дія агента 1, стовпець — агента 2. П'ять класичних ігор показують домінування, кілька рівноваг, ризик і координацію.


<Figure src="/figs/ext/m05-matrix-games.png" alt="Три гри в нормальній формі для двох агентів">

Джерело: [Albrecht, Christianos, Schäfer, 2024](https://www.marl-book.com/), рис. 3.2. Три матричні гри двох агентів: (a) «камінь–ножиці–папір» (R — камінь, P — папір, S — ножиці), (b) гра координації (A чи B), (c) дилема в'язня (C — співпрацювати, D — зрадити). У (a) і (c) у клітинці дві винагороди — агента 1 і агента 2; у (b) одна, спільна для обох.

</Figure>


Характер гри задає співвідношення винагород.

| **Клас гри** | **Умова на винагороди** | **Приклад на рисунку** |
|---|---|---|
| з нульовою сумою (*zero-sum*) | $\sum_{i} R_i(a) = 0$ для кожної $a$; для двох — $R_1 = -R_2$ | (a): виграш одного — програш іншого |
| зі спільною винагородою (*common-reward*) | $R_1(a) = \dots = R_n(a)$ | (b): обидва отримують 10, якщо обрали однаково, і 0 — якщо ні |
| із загальною сумою (*general-sum*) | обмежень немає | (c): інтереси частково збігаються |

### Дилема в'язня і полювання на оленя

**Дилема в'язня** (*Prisoner's Dilemma*). Дія C (*cooperate*) — співпрацювати, D (*defect*) — зрадити.

| **агент 1 \ агент 2** | **C** | **D** |
|---|---|---|
| **C** | −1, −1 | −5, 0 |
| **D** | 0, −5 | −3, −3 |

Дія D **домінантна**: вона краща за будь-якої дії суперника. Якщо суперник грає C, то D дає 0 замість −1; якщо D — то −3 замість −5. Тож обидва грають D і отримують (−3, −3), хоча (C, C) з (−1, −1) вигідніша обом. Стійкий результат і найкращий спільний — різні речі. У повторюваній дилемі можлива, наприклад, політика Tit-for-Tat («зуб за зуб»): спершу співпрацювати, далі повторювати останню дію суперника.

**Полювання на оленя** (*Stag Hunt*). Двоє мисливців обирають між оленем (S, *stag*) — взяти його можна лише разом — і зайцем (H, *hare*), якого кожен бере сам.

| **агент 1 \ агент 2** | **S** | **H** |
|---|---|---|
| **S** | 4, 4 | 0, 3 |
| **H** | 3, 0 | 2, 2 |

Тут стійких результатів два: (S, S) з (4, 4) і (H, H) з (2, 2). (S, S) краща обом — її називають **домінантною за винагородою** (*reward-dominant*). (H, H) — **домінантна за ризиком** (*risk-dominant*): H гарантує щонайменше 2, хай що робить напарник, а S може дати 0. Для рою це маневр, що вдається лише разом, — підняти вантаж удвох.

### «Хто зверне» і битва статей

**«Хто зверне»** (*Chicken*) — та сама зустріч біля кишені, матрицю якої ми бачили в частині 1.

Стійкі пари — (S, L) і (L, S): поступається хтось один. Пара (L, L) з (6, 6) дає найбільшу суму, але з неї кожному вигідно перейти на S і отримати 7 замість 6. Для рою це розходження двох апаратів у вузькому проході.

**Битва статей** (*Battle of the Sexes*). Двоє хочуть бути разом, але один воліє місце A, інший — B.

| **агент 1 \ агент 2** | **A** | **B** |
|---|---|---|
| **A** | 10, 7 | 2, 2 |
| **B** | 0, 0 | 7, 10 |

A — улюблене місце агента 1, B — агента 2; розминулися — по 2, якщо кожен пішов у своє, і по 0, якщо в чуже. Стійкі пари — (A, A) і (B, B); важко домовитися, яку обрати, без каналу для домовленостей. Для рою це вибір спільної точки збору чи спільної частоти.

### Пошук детермінованих рівноваг

«Стійка пара» з попередніх карток має точну назву — **рівновага Неша**: спільна дія, від якої жодному агентові не вигідно відхилитися самому. Дія агента, найкраща проти фіксованих дій інших, — його **найкраща відповідь** (*best response*). Рівновага — це пара, у якій дія кожного є найкращою відповіддю на дію іншого. Перевірка завжди однакова: зафіксувати дію суперника й подивитися, чи є в агента щось краще. **Детермінована** рівновага — та, де кожен агент обирає одну дію з імовірністю 1.


<CodeFold title="Шукає детерміновані рівноваги Неша в п'яти матричних іграх" :lines="28" sec="0.1">

```python
import itertools

import numpy as np


def pure_nash(R1, R2, names1, names2):
    """Повертає всі пари, від яких жодному агентові не вигідно відхилитись."""
    eq = []
    for i, j in itertools.product(range(R1.shape[0]), range(R1.shape[1])):
        best1 = R1[i, j] >= R1[:, j].max()  # агент 1 не покращить, змінивши рядок
        best2 = R2[i, j] >= R2[i, :].max()  # агент 2 не покращить, змінивши стовпець
        if best1 and best2:
            eq.append(f"({names1[i]},{names2[j]}) -> ({R1[i, j]:+d},{R2[i, j]:+d})")
    return eq


RPS1 = np.array([[0, -1, 1], [1, 0, -1], [-1, 1, 0]])
GAMES = {  # виплати агента 1 (рядок), агента 2 (стовпець), назви дій
    "Prisoner's Dilemma": ([[-1, -5], [0, -3]], [[-1, 0], [-5, -3]], "CD"),
    "Stag Hunt": ([[4, 0], [3, 2]], [[4, 3], [0, 2]], "SH"),
    "Chicken": ([[0, 7], [2, 6]], [[0, 2], [7, 6]], "SL"),
    "Battle of the Sexes": ([[10, 2], [0, 7]], [[7, 2], [0, 10]], "AB"),
    "Rock-Paper-Scissors": (RPS1, -RPS1, "RPS"),
}
for name, (R1, R2, acts) in GAMES.items():
    eq = pure_nash(np.array(R1), np.array(R2), acts, acts)
    found = "; ".join(eq) or "детермінованих рівноваг немає"
    print(f"{name:22s} {found}")
```

### Імовірнісні рівноваги: умова байдужості

**Імовірнісна політика** (*mixed strategy*) обирає дію навмання із заданими ймовірностями. Позначимо $p$ — імовірність, що агент 1 обирає перший рядок, і $q$ — що агент 2 обирає перший стовпець.

Імовірнісна рівновага тримається на **умові байдужості**: агент змішує дії лише тоді, коли вони дають йому однакову очікувану винагороду. У «хто зверне» агент 2 грає S з імовірністю $q$, і агенту 1 мають бути однаково вигідні обидві дії:

$$\underbrace{0\cdot q + 7\,(1-q)}_{\text{агент 1 грає S}} \;=\; \underbrace{2\,q + 6\,(1-q)}_{\text{агент 1 грає L}} \quad\Rightarrow\quad 7 - 7q = 6 - 4q \quad\Rightarrow\quad q = \tfrac{1}{3}$$

Кожна дія тоді дає агенту 1 $7 - 7/3 = 14/3 \approx 4{,}67$. Гра симетрична, тож і $p = 1/3$. Код нижче розв'язує ту саму умову для чотирьох ігор 2 × 2 і перевіряє «камінь–ножиці–папір» з 1/3 на кожну дію. $U_1$, $U_2$ у виводі — очікувані віддачі агентів, а $\tilde R_1(S)$, $\tilde R_1(H)$ — середня винагорода агента 1 за кожну дію проти агента 2, що обирає S з імовірністю $q$ (докладно — у частинах 3 і 5).


*Продовження блоку «Шукає детерміновані рівноваги Неша в п'яти матричних іграх»: цей код виконується разом із ним.*

<CodeFold title="Імовірнісні рівноваги з умови байдужості і світ очима агента 1" :lines="32" sec="0.1">

```python
# продовження блоку «Шукає детерміновані рівноваги»
def mixed_2x2(R1, R2):
    """p — агент 1 грає перший рядок, q — агент 2 грає перший стовпець.

    q робить агенту 1 байдужим вибір рядка, p робить агенту 2 байдужим
    вибір стовпця. Повертає p, q і очікувані виплати обох.
    """
    A, B = np.array(R1, float), np.array(R2, float)
    q = (A[1, 1] - A[0, 1]) / (A[0, 0] - A[0, 1] - A[1, 0] + A[1, 1])
    p = (B[1, 1] - B[1, 0]) / (B[0, 0] - B[1, 0] - B[0, 1] + B[1, 1])
    x, y = np.array([p, 1 - p]), np.array([q, 1 - q])
    return p, q, x @ A @ y, x @ B @ y


print("гра                       p      q    U1     U2")
for name, (R1, R2, _) in list(GAMES.items())[:4]:
    p, q, u1, u2 = mixed_2x2(R1, R2)
    if 0 <= p <= 1 and 0 <= q <= 1:
        print(f"{name:22s} {p:6.3f} {q:6.3f} {u1:5.2f} {u2:6.2f}")
    else:
        print(f"{name:22s} імовірнісної рівноваги немає: D домінує")
third = np.full(3, 1 / 3)  # Rock-Paper-Scissors: кожна дія з імовірністю 1/3
print("RPS проти 1/3, 1/3, 1/3: виплата кожної дії", np.array(RPS1) @ third)
R1 = np.array(GAMES["Stag Hunt"][0])  # виплати агента 1: рядок — його дія
print("q = P(агент 2 грає S)   R̃1(S)   R̃1(H)   краща дія агента 1")
for q in (0.2, 0.5, 2 / 3, 0.9):
    pi2 = np.array([q, 1 - q])
    v = R1 @ pi2  # R̃1(a1) = R1(a1, S)·q + R1(a1, H)·(1 − q)
    best = "S" if v[0] > v[1] + 1e-9 else "H" if v[1] > v[0] + 1e-9 else "байдуже"
    print(f"{q:22.2f} {v[0]:8.2f} {v[1]:8.2f}   {best}")
mix = np.array([1 / 2, 1 / 4, 1 / 4])  # агент 1 відступив від 1/3, 1/3, 1/3
print("RPS, агент 1 грає (1/2, 1/4, 1/4): виплата проти R, P, S =", mix @ RPS1)
```

## Частина 3 · Концепції розв'язку

Розв'язок гри — це не одна політика, а **спільна політика** $\pi = (\pi_1,\dots,\pi_n)$, по одній на агента. Що вважати добрим розв'язком, залежить від мети: стійкість до відхилень, неможливість покращити всім одразу, найбільша сума чи найрівномірніший розподіл. Ця частина дає кожному критерію формулу й число на іграх лекції.

### Очікувана віддача й найкраща відповідь

Коли агенти змішують дії, кожна клітинка матриці трапляється з якоюсь імовірністю. Очікувана віддача агента $i$ — середня винагорода, зважена цими ймовірностями:

$$U_i(\pi) = \sum_{a\in A} R_i(a)\prod_{j\in I}\pi_j(a_j)$$

У «хто зверне» з $p = q = 1/3$ чотири клітинки мають імовірності $1/9,\ 2/9,\ 2/9,\ 4/9$, і віддача агента 1

$$U_1 = \tfrac{1}{9}\cdot 0 + \tfrac{2}{9}\cdot 7 + \tfrac{2}{9}\cdot 2 + \tfrac{4}{9}\cdot 6 = \tfrac{42}{9} \approx 4{,}67$$

— те саме число, що надрукував код. У стохастичній грі віддачу рахують по всьому польоту з дисконтом: $U_i(\pi) = \mathbb{E}\big[\sum_t \gamma^t R_i(s^t,a^t,s^{t+1})\big]$, де $\gamma$ — коефіцієнт дисконтування.

Найкращу відповідь і рівновагу ми бачили для детермінованих дій; тепер поширимо їх на ймовірнісні політики. Позначення: $\pi_{-i}$ — політики всіх агентів, крім $i$; $a_{-i}$ — їхні дії; $\langle a_i, a_{-i}\rangle$ — спільна дія, складена з дії $a_i$ агента $i$ і дій решти. **Найкраща відповідь** агента $i$ — політика, що дає найбільшу віддачу проти фіксованих політик інших:

$$BR_i(\pi_{-i}) = \arg\max_{\pi_i} U_i(\pi_i,\pi_{-i})$$

Як вона змінюється разом із політикою іншого, на числах Stag Hunt покаже виклик 1.

### Рівновага Неша й мінімакс

**Рівновага Неша** — спільна політика, у якій політика кожного агента є найкращою відповіддю на політики решти:

$$\forall i,\ \forall \pi_i':\quad U_i(\pi_i',\pi_{-i}) \le U_i(\pi)$$

Відхилитися самому не вигідно нікому — і нічого більшого рівновага не обіцяє. Неш довів (1950), що кожна скінченна гра має щонайменше одну рівновагу, можливо ймовірнісну. Знайти її важко: задача PPAD-повна (Daskalakis et al., 2009) — розв'язок існує, але ефективного алгоритму для будь-якої гри не відомо. Тому MARL не шукає рівновагу точно, а навчається достатньо доброї спільної політики з досвіду.

Для двох агентів у грі з нульовою сумою є простіший погляд — **мінімакс**: агент 1 обирає політику, що максимізує його найгірший результат.

$$\max_{\pi_1}\ \min_{\pi_2}\ U_1(\pi_1,\pi_2) \;=\; \min_{\pi_2}\ \max_{\pi_1}\ U_1(\pi_1,\pi_2)$$

Що обидва боки рівні для ймовірнісних політик, довів фон Нейман (1928, теорема про мінімакс); це число називають **значенням гри**, і тут мінімакс збігається з рівновагою Неша. Шеплі (Shapley, 1953) поширив цю ідею на стохастичні ігри з нульовою сумою: у кожному стані замість $V^*(s')$ береться значення гри. У «камені–ножицях–папері» значення 0: рівномірна політика гарантує 0 проти будь-кого, а відхилення суперник використає. Якщо агент 1 грає (1/2, 1/4, 1/4), то проти паперу отримує $\tfrac12\cdot(-1) + \tfrac14\cdot 0 + \tfrac14\cdot 1 = -0{,}25$ — останній рядок виводу коду імовірнісних рівноваг.

### Парето-оптимальність, добробут і справедливість

Рівновага питає, чи хоче хтось змінити дію сам; інші критерії дивляться на результат для всіх.

Спільна політика $\pi$ **Парето-оптимальна**, якщо немає іншої $\pi'$, яка нікому не гірша й комусь краща:

$$\nexists\,\pi':\quad U_i(\pi') \ge U_i(\pi)\ \ \forall i \quad\text{і}\quad U_j(\pi') > U_j(\pi)\ \text{хоча б для одного } j$$

Серед детермінованих клітинок ігор лекції Парето-оптимальні такі: у «хто зверне» — (S, L), (L, S) і (L, L); у дилемі в'язня — усі, крім рівноваги (D, D), бо (C, C) краща обом; у Stag Hunt — лише (S, S); у битві статей — (A, A) і (B, B).

**Добробут** (*welfare*) — сума віддач, **справедливість** (*fairness*) — їхній добуток:

$$W(\pi) = \sum_{i\in I}U_i(\pi), \qquad F(\pi) = \prod_{i\in I}U_i(\pi)$$

Парето-оптимальність не означає найбільшого добробуту. Клітинка (S, L) у «хто зверне» Парето-оптимальна, але її добробут $7 + 2 = 9$ менший за $6 + 6 = 12$ у (L, L). Справедливість розрізняє однакові за добробутом політики: (1, 5), (2, 4) і (3, 3) мають $W = 6$, але $F$ = 5, 8 і 9. Добуток має сенс лише за додатних віддач: у дилемі в'язня $(-3)\cdot(-3) = 9 > (-1)\cdot(-1) = 1$, хоча (D, D) гірша обом.

Джерело: [Albrecht, Christianos, Schäfer, 2024](https://www.marl-book.com/), рис. 4.4. Гра «хто зверне»: кожна синя точка — пара очікуваних віддач (*joint return*), яку дає якась пара ймовірнісних політик; горизонтальна вісь — віддача агента 2, вертикальна — агента 1. ### Централізоване проти незалежного навчання

Є два прямі способи звести багатоагентну задачу до знайомого Q-навчання (*Q-learning*) з модуля 04.

**Централізоване Q-навчання** (*central Q-learning*, CQL) вчить одну таблицю $Q(s, a)$ над спільними діями, ніби обома дронами керує один агент. У коридорі це 43 стани × 9 спільних дій = 387 чисел. **Незалежне Q-навчання** (*independent Q-learning*, IQL) дає кожному дрону власну таблицю $Q_i(s, a_i)$ над його трьома діями: 43 × 3 = 129 чисел на дрон. Правило оновлення кожного дрона — звичайне Q-навчання з модуля 04:

$$Q_i(s,a_i) \leftarrow Q_i(s,a_i) + \alpha\big[r + \gamma \max_{a_i'} Q_i(s',a_i') - Q_i(s,a_i)\big]$$

Дія іншого дрона в цій формулі не з'являється: вона прихована в тому, куди саме перейшов стан і яку винагороду отримано.

| **Аспект** | **Централізоване (CQL)** | **Незалежне (IQL)** |
|---|---|---|
| що навчається | одна таблиця на спільні дії | у кожного агента своя таблиця на свої дії |
| винагорода | потрібна одна: кортеж винагород зводять до числа (у коридорі вона й так спільна) | у кожного своя, зводити не треба |
| дій на стан | $\lvert A_1\rvert\cdot\lvert A_2\rvert$ = 9 | $\lvert A_i\rvert$ = 3 |
| виконання | потрібен центр, що бачить усіх і розсилає дії | повністю розподілене |
| головна проблема | масштаб і спосіб зведення винагород | нестаціонарність: інший агент теж змінюється |

### Коридор: CQL проти IQL на п'яти зернах

Код навчає три варіанти на тих самих 5 зернах по 3 000 епізодів: CQL з повним станом, IQL з повним станом і IQL, у якому кожен дрон бачить лише свій сенсор радіусом 1 — це POSG із частини 1. Його таблиця залежить лише від поточного спостереження, без історії. Дослідження ε-жадібне: $\epsilon$ спадає від 1 до 0,05 за перші 1 000 епізодів, темп $\alpha = 0{,}1$, без дисконту. Політ обмежено 20 кроками. Кожні 100 епізодів навчання зупиняють і пускають **жадібний політ** зі старту — без дослідження, за найбільшою Q. Параметри обрано до прогону. Стовпець «оновлень» — скільки разів оновилася кожна таблиця в зерні 0: у IQL обидві однаково часто, тож навчаються обидва дрони.

```python
            rng.integers(n) if rng.random() < e else int(np.argmax(q(i, s)))
            for i in range(tabs)

        return idx, JOINT[idx[0]] if kind == "CQL" else tuple(idx)

    curve, updates = [], [0] * tabs

                ret += r
                if done:
                    break
            curve.append((ret, s == (HOME, HOME)))
    return np.array(curve), updates, Q
```

## Частина 5 · Чотири виклики MARL

Прогін у коридорі вже показав, що незалежне навчання поступається централізованому навіть у задачі з 43 станами. Причин кілька, і кожна має назву. Чотири виклики цієї частини — властивості самої багатоагентної задачі, а не вади конкретного алгоритму: **нестаціонарність**, **вибір рівноваги**, **розподіл заслуг** (*credit assignment*) і **масштабування**.

### Виклик 1: нестаціонарність

Агент $i$ бачить лише власну дію, а перехід стану визначає спільна. Тому динаміка, яку він «спостерігає», — це справжня динаміка гри, усереднена за політиками решти:

$$T_i(s'\mid s,a_i) = \sum_{a_{-i}}T\big(s'\mid s,\langle a_i,a_{-i}\rangle\big)\prod_{j\ne i}\pi_j(a_j\mid s)$$

| **Позначення** | **Значення** |
|---|---|
| $T_i$ | динаміка, як її бачить агент $i$ |
| $T$ | справжня динаміка гри над спільними діями |
| $\pi_j$ | політика агента $j$, що змінюється, поки той навчається |

Поки сусіди вчаться, $\pi_j$ змінюються, а з ними й те, що агент $i$ вважає законом середовища. На коридорі: у стані (1, 3) синій летить уперед, і ймовірність зіткнення, яку він «бачить», — це ймовірність, що помаранчевий теж полетить уперед, $\pi_{\text{пом}}(\text{вперед}\mid(1,3))$: 0,5, якщо помаранчевий обирає «вперед» у половині випадків, і майже 0, коли він навчився чекати. Q-навчання сходиться за умови, що $T$ і $R$ не змінюються (і кожна пара «стан — дія» трапляється нескінченно часто, а $\alpha$ спадає), — і саме перша умова тут порушена.

У матричній грі те саме видно на винагороді. Агент 1 у Stag Hunt бачить середню винагороду своєї дії $\tilde R_1(a_1) = \sum_{a_2} R_1(a_1, a_2)\,\pi_2(a_2)$. Якщо агент 2 обирає S з імовірністю $q$, то $\tilde R_1(S) = 4q$ і $\tilde R_1(H) = 3q + 2(1-q) = 2 + q$. За $q = 0{,}2$ краща H (2,2 проти 0,8), за $q = 0{,}9$ — S (3,6 проти 2,9), а перемикання відбувається при $4q = 2 + q$, тобто $q = 2/3$. Ці рядки друкує код імовірнісних рівноваг.

### Нестаціонарність у прогоні

Тепер мисливці навчаються незалежним Q-навчанням. Стану немає, тож кожен вчить два числа $Q_i(S)$ і $Q_i(H)$ за правилом $Q_i(a_i) \leftarrow Q_i(a_i) + \alpha\,\big(r_i - Q_i(a_i)\big)$. Дослідження ε-жадібне з постійним $\epsilon = 0{,}1$, $\alpha = 0{,}1$, 2 000 раундів, 5 зерен; нічию між діями розбиває жереб. Прогін повторено з $Q_0 = 0$ і з **оптимістичним стартом** $Q_0 = 5$ — більше за найбільшу винагороду 4, тож кожна дія здається привабливою, доки її не спробують. Наприкінці код запускає «монетки» (*matching pennies*): обидва одночасно кладуть монету орлом (О) чи решкою (Р) догори; агент 1 виграє 1, якщо сторони збіглися, і програє 1, якщо ні.

| **агент 1 \ агент 2** | **О** | **Р** |
|---|---|---|
| **О** | 1, −1 | −1, 1 |
| **Р** | −1, 1 | 1, −1 |

Детермінованої рівноваги тут немає, а ймовірнісну дає та сама умова байдужості: агенту 1 байдуже, коли $q - (1 - q) = -q + (1 - q)$, тобто $q = 1/2$.


<CodeFold title="Незалежне Q-навчання на Stag Hunt на п'яти зернах, потім «монетки»" :lines="57" sec="0.4">

```python
import numpy as np

EPS, ALPHA, ROUNDS, SEEDS = 0.1, 0.1, 2000, range(5)  # обрано до прогону


def greedy(q, rng):
    return int(rng.choice(np.flatnonzero(q == q.max())))  # нічию розбиває жереб


def iql(R1, R2, seed, q0=0.0):
    """Незалежне Q-навчання двох агентів у повторюваній матричній грі.

    Кожен агент знає лише власні дії та винагороди. Повертає журнал:
    жадібна дія кожного агента й Q обох після кожного раунду.
    """
    rng = np.random.default_rng(seed)
    Q, log, updates = [np.full(2, q0), np.full(2, q0)], [], [0, 0]
    for _ in range(ROUNDS):
        a = [
            rng.integers(2) if rng.random() < EPS else greedy(Q[i], rng) for i in (0, 1)
        ]
        r = (R1[a[0], a[1]], R2[a[0], a[1]])
        for i in (0, 1):
            Q[i][a[i]] += ALPHA * (r[i] - Q[i][a[i]])  # Q ← Q + α(r − Q)
            updates[i] += 1
        log.append([int(Q[0][1] > Q[0][0]), int(Q[1][1] > Q[1][0]), *Q[0], *Q[1]])
    return np.array(log), updates


SH1, SH2 = np.array([[4, 0], [3, 2]]), np.array([[4, 3], [0, 2]])  # дії: S, H
print(f"ε = {EPS}, α = {ALPHA}, раундів {ROUNDS}, зерен {len(SEEDS)}")
counts = set()  # скільки разів оновився кожен агент — в усіх 10 прогонах
for q0 in (0.0, 5.0):
    ends = []
    for seed in SEEDS:
        log, upd = iql(SH1, SH2, seed, q0)
        counts.add(tuple(upd))
        pair = "".join("SH"[int(x)] for x in log[-1, :2])  # кінцеві жадібні дії
        flips = np.flatnonzero(np.any(np.diff(log[:, :2], axis=0) != 0, axis=1))
        ends.append(f"{pair} з раунду {flips[-1] + 2 if len(flips) else 1}")
    print(f"Q0 = {q0}: {ends}")
print(f"оновлень на агента, усі 10 прогонів: {sorted(counts)}")
MP1 = np.array([[1, -1], [-1, 1]])  # агент 1 виграє, коли монети збіглися
log, _ = iql(MP1, -MP1, seed=0)
pairs = [tuple(int(x) for x in row[:2]) for row in log]
seq = [pairs[0]] + [b for a, b in zip(pairs, pairs[1:], strict=False) if a != b]
name = {(0, 0): "(О,О)", (0, 1): "(О,Р)", (1, 1): "(Р,Р)", (1, 0): "(Р,О)"}
ring = [(0, 0), (0, 1), (1, 1), (1, 0)]  # коло: агент 2 тікає, агент 1 наздоганяє
forward = sum(
    ring.index(b) == (ring.index(a) + 1) % 4 for a, b in zip(seq, seq[1:], strict=False)
)
print(f"«монетки»: раундів {len(pairs)}")
print("перші зміни жадібних дій:", " → ".join(name[p] for p in seq[:9]))
changes = len(seq) - 1
print(f"змін пари {changes}: за колом {forward}, проти кола {changes - forward}")
freq = 1 - log[:, :2].mean(axis=0)
print(f"частка раундів, коли жадібна дія — «орел»: {freq[0]:.2f} і {freq[1]:.2f}")
```

### Виклик 2: вибір рівноваги

У Stag Hunt в усіх п'яти зернах IQL закінчує в (H, H), безпечнішій рівновазі. Навіть коли пара починає з (S, S), як у зернах 2 і 3, вона не втримується: дослідження напарника раз у раз дає за S нуль, і кілька таких раундів поспіль опускають $Q(S)$ нижче $Q(H)$; назад шляху практично немає — у (H, H) спроба S дає 0 проти 2. Оптимістичний старт $Q_0 = 5$ кінця не змінив: у трьох зернах (H, H) встановилася пізніше, в одному так само, в одному раніше. Кращу для обох (S, S) незалежні агенти не утримують — це і є виклик **вибору рівноваги**. У коридорі його видно у віджеті: в різних зернах пірнає то синій, то помаранчевий.

Чи сходиться IQL взагалі, показують «монетки» (одне зерно, 0): детермінованої рівноваги немає, і жадібні дії ходять по колу — агент 2 тікає від збігу, агент 1 наздоганяє. З 289 змін пари 274 ідуть за колом (О,О) → (О,Р) → (Р,Р) → (Р,О). За весь прогін кожна дія жадібна приблизно в половині раундів (0,48 і 0,50) — поруч з імовірнісною рівновагою 1/2, але сама політика до неї не сходиться.

### Виклик 3: розподіл заслуг

В одноагентному RL розподіл заслуг — питання «яка з моїх минулих дій принесла цю винагороду». У багатоагентному додається друге: **чия саме дія**. Зі спільною винагородою воно найгостріше: одне число отримують усі.

Одна з відомих відповідей — **різницева винагорода** (*difference reward*, Wolpert, Tumer, 2002): порівняти спільну винагороду з тією, що була б без внеску агента.

$$D_i = G(a) - G\big(\langle \tilde a_i,\ a_{-i}\rangle\big)$$

Тут $G(a)$ — спільна винагорода за спільну дію $a$, а $\tilde a_i$ — **дія за замовчуванням**, якою замінюють дію агента $i$. На коридорі: у стані (2, 3) спільна дія (чекати, вперед) — зіткнення, −50. З дією за замовчуванням «чекати» вийшло б (чекати, чекати) і −2, тож $D_{\text{пом}} = -50 - (-2) = -48$, а $D_{\text{синій}} = -50 - (-50) = 0$: зіткнення спричинив помаранчевий. У задачі нижче дія за замовчуванням — «лишитися на базі». Приклад — чотири БПЛА обстежують три сектори різної цінності (A — 3, B — 2, C — 1,5); кожен виліт коштує 0,3 енергії, а сектор зараховують один раз, хоч би скільки апаратів туди прилетіло.


<CodeFold title="Різницеві винагороди для чотирьох БПЛА" :lines="27" sec="0.0">

```python
import itertools

VALUE = {"A": 3.0, "B": 2.0, "C": 1.5}  # цінність обстеження сектора
COST, BASE = 0.3, "база"  # енергія за виліт; дія за замовчуванням — лишитися на базі


def team_reward(plan):
    """Спільна винагорода: цінність покритих секторів мінус енергія вильотів."""
    covered = {sector for sector in plan if sector != BASE}
    flying = sum(sector != BASE for sector in plan)
    return sum(VALUE[s] for s in covered) - COST * flying


def difference(plan, i):
    """D_i = G(a) − G(a з дією агента i, заміненою на «база»)."""
    without = list(plan)
    without[i] = BASE
    return team_reward(plan) - team_reward(without)


plan = ["A", "B", "B", BASE]  # куди полетіли БПЛА 1–4
G = team_reward(plan)
print(f"план {plan}: спільна винагорода G = {G:.1f} — її отримує кожен")
for i, sector in enumerate(plan):
    print(f"БПЛА {i + 1} ({sector:4s}): D = {difference(plan, i):+.1f}")
best = max(itertools.product([*VALUE, BASE], repeat=4), key=team_reward)
print(f"найкращий план {list(best)}: G = {team_reward(best):.1f}")
```

### Висновки

- Задача MARL — це пара «модель гри + концепція розв'язку». На одному коридорі видно всі моделі: одна зустріч — гра в нормальній формі, політ — стохастична гра з 43 станами, політ із сенсором — POSG, зі спільною винагородою — Dec-POMDP.
- Рівновага Неша означає лише стійкість до одностороннього відхилення. Їх може бути кілька (Stag Hunt, «хто зверне», битва статей), вона буває гіршою за нерівноважний варіант (дилема в'язня) або лише ймовірнісною («камінь–ножиці–папір»).
- Парето не означає найбільшого добробуту: (S, L) дає 9, а (L, L) — 12.
- У коридорі CQL дійшов до оптимуму −13 у всіх п'яти зернах; IQL розходиться раніше, але до оптимуму дійшов лише в одному зерні й у середньому зупиняється на −15.
- Чотири виклики на даних: нестаціонарність (найкраща дія агента 1 у Stag Hunt перемикається при $q = 2/3$), вибір рівноваги (IQL у всіх зернах обирає безпечну (H, H)), розподіл заслуг (спільні 4,1 проти різницевих +2,7 / −0,3 / −0,3 / 0) і масштабування (6⁸ ≈ 1,7 млн спільних дій).
- Практичний компроміс — CTDE: навчання зі станом усіх у симуляторі, політ за власним спостереженням.

### Довідка: типи ігор і словник

Перш ніж обирати алгоритм для задачі рою, варто визначити тип гри: від нього залежить, чи шукати рівновагу і яку.

| **Тип гри** | **Задача рою** | **Головна складність** |
|---|---|---|
| з нульовою сумою, 2 агенти | перехоплення, ухилення | гарантія проти найгіршого |
| зі спільною винагородою (Dec-POMDP) | обстеження, доставка, коридор лекції | розподіл заслуг, хто поступиться |
| полювання на оленя | маневр, що вдається лише разом | вигідна чи безпечна рівновага |
| «хто зверне» | прохід з окремими винагородами | обидва не поступляться |
| битва статей | спільна точка збору чи частота | дві детерміновані рівноваги |
| загальна сума, $n$ агентів | кілька операторів в одному просторі | кооперація й конкуренція водночас |

Ті самі поняття в літературі з теорії ігор звуть інакше: середовище — гра (*game*), агент — гравець (*player*), винагорода — виплата (*payoff*), політика — стратегія (*strategy*), детермінована — чиста (*pure*), імовірнісна — змішана (*mixed*), спільна дія — профіль дій (*action profile*).

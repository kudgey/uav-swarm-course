# Модуль 05 · Глибоке навчання з підкріпленням: від DQN до PPO

Як замінити таблицю цінностей нейромережею, що від цього ламається і як це лагодять DQN, градієнт політики, актор–критик і PPO. Усі методи лекції розв'язують ту саму задачу — дрон має висіти на висоті метр, — тож їх можна порівняти на одних числах.

### Зміст лекції

Модуль 04 зберігав цінність кожного стану в окремій комірці таблиці. Ця лекція замінює таблицю нейромережею й іде двома шляхами, які сходяться в актор–критику, а з ним — у PPO. Наскрізна задача одна: модель Crazyflie має висіти на висоті метр. Кожен метод ми запускаємо на ній по-справжньому й показуємо, що вийшло.

**Частина 1** показує, як виглядала таблиця Q, чому для дрона вона здебільшого порожня і що саме заміняє мережа.

**Частина 2** — DQN. Спершу дві проблеми наївного підходу на справжній мережі, потім смертельна тріада на прикладі з двома станами, а тоді два механізми DQN окремо: буфер повторів і заморожена копія мережі. Наприкінці — повний алгоритм крок за кроком і результат на задачі висіння.

**Частини 3 і 4** — другий шлях: вчити політику напряму. REINFORCE робить удалі дії ймовірнішими, актор–критик зменшує шум за допомогою переваги. Обидва алгоритми ми розбираємо по кроках і порівнюємо на тій самій задачі.

**Частина 5** — PPO: як обмежити крок оновлення і що алгоритм вимірює на кожному оновленні.

**Частина 6** — PPO вчиться висіти: справжній прогін, політ крок за кроком на різних етапах навчання і порівняння всіх методів на одній задачі.

### Результати навчання

Після лекції ви зможете:

- показати на прикладі, що саме заміняє мережа $Q(s,a;\theta)$, і пояснити, чому таблиця для дрона здебільшого порожня;
- пояснити дві проблеми наївного глибокого Q-навчання — рухому ціль і корельовані вибірки — і показати їх на справжній мережі;
- назвати три складники смертельної тріади й показати на прикладі w → 2w, що досить прибрати будь-який один;
- описати, як працюють *replay buffer* і *target network*, і пройти один крок навчання DQN з числами;
- порахувати віддачу від кожного кроку епізоду й один крок REINFORCE;
- пояснити, навіщо актор–критик замінює віддачу перевагою, і прочитати одне оновлення A2C;
- описати цикл PPO, порахувати ціль з обрізанням і прочитати телеметрію навчання;
- порівняти алгоритми на одній задачі за кількома зернами й окремими тестовими стартами.

### Карта лекції

Верхній ряд — шлях через цінності: від таблиці до DQN. Стрілка вниз — другий шлях, потрібний для неперервних дій: вчити політику напряму. Шляхи сходяться в актор–критику: його критик — мережа цінності з TD-ціллю, тобто ідея першого шляху. Далі PPO і приклад із дроном. Наприкінці ця сама карта повернеться з головним числом кожної теми.

### Наскрізна задача: висіння дрона

Задачу поставлено в модулі 04: нанодрон має висіти на висоті метр. Політика бачить два числа — похибку висоти $z - 1$ і вертикальну швидкість $v_z$ — і видає тягу. Параметри взято з моделі Crazyflie 2.1 у симуляторі gym-pybullet-drones, а навчаємо на власній одновимірній моделі `Hover1D`: маса 27 г (за паспортом 29 г), максимальна тяга в 2,25 раза більша за вагу, тобто 0,596 Н. Тож для висіння досить 0,44 максимальної тяги. Політика видає нормовану тягу $u$ від 0 до 1 на 50 Гц, крок триває 0,02 с, епізод — 8 с, або 400 кроків.

Винагорода за крок складається з чотирьох доданків:

$$r_t = -\lvert z - 1{,}0 \rvert - 0{,}20\,\lvert v_z \rvert - 0{,}05\,\lvert u_t - u_{t-1} \rvert + 0{,}10$$

Перший тримає висоту, другий не дає пружинити, третій штрафує смикання моторів, останній — **бонус за життя**: без нього всі доданки від'ємні, і агентові вигідно швидко впасти, щоб обірвати епізод. Ідеальне висіння дає $+0{,}10$ за крок, тобто $+5{,}0$ за секунду. Епізод обривається аварією, якщо апарат опустився нижче 5 см або відлетів від цілі далі ніж на метр.


<Figure src="/figs/own/m04-hover-step.png" alt="Один крок задачі висіння: два числа спостереження, політика, тяга й фізика кроку">

Один крок задачі висіння: два числа спостереження, політика, тяга й фізика кроку

</Figure>


Код нижче — клас `Hover1D`. Усі алгоритми лекції працюють саме з ним. Для перевірки він рахує один крок із рисунка: апарат на 13 см нижче цілі опускається зі швидкістю 12 см/с, політика дала тягу 0,62. Швидкість падіння зменшилася до 4 см/с, але винагорода ще від'ємна: бонус 0,1 перекриває штраф за висоту лише ближче ніж 10 см від цілі.


<CodeFold title="Середовище висіння: один крок фізики й винагороди без округлень" :lines="39" sec="0.1">

```python
import numpy as np

M, G, T_MAX = 0.027, 9.81, 0.596  # маса, кг; g, м/с²; максимальна тяга, Н
DT, Z_REF, STEPS = 0.02, 1.0, 400  # крок 0,02 с (50 Гц), ціль 1 м, епізод 8 с
W_Z, W_V, W_U, BONUS = 1.00, 0.20, 0.05, 0.10  # ваги винагороди


class Hover1D:
    """Вертикальний рух Crazyflie: політика задає нормовану тягу u ∈ [0, 1]."""

    def reset(self, rng, z_range=(0.8, 1.2)):
        self.z, self.v = rng.uniform(*z_range), rng.uniform(-0.2, 0.2)
        self.u, self.t = M * G / T_MAX, 0  # попередня тяга — рівноважна
        return self.obs()

    def obs(self):
        return np.array([self.z - Z_REF, self.v], dtype=np.float32)

    def step(self, u):
        u = float(np.clip(u, 0.0, 1.0))
        a = (u * T_MAX - M * G) / M  # прискорення, м/с²
        self.z, self.v = self.z + self.v * DT, self.v + a * DT
        parts = (
            -W_Z * abs(self.z - Z_REF),  # тримати висоту
            -W_V * abs(self.v),  # не пружинити
            -W_U * abs(u - self.u),  # не смикати мотори
            BONUS,  # бонус за життя
        )
        self.u, self.t = u, self.t + 1
        crashed = self.z < 0.05 or abs(self.z - Z_REF) > 1.0
        return self.obs(), sum(parts), crashed, self.t >= STEPS, parts


env = Hover1D()
env.z, env.v, env.u, env.t = 0.870, -0.12, 0.600, 0  # стан із прикладу
obs, r, crashed, timeout, parts = env.step(0.620)
print(f"нова висота {env.z:.4f} м, нова швидкість {env.v:+.4f} м/с")
print("доданки винагороди:", "  ".join(f"{p:+.4f}" for p in parts))
print(f"винагорода за крок: {r:+.4f}")
```

### Три рівні тяги і як ми міряємо результат

DQN, REINFORCE і A2C у цій лекції обирають одну з **трьох дій**: менше тяги ($0{,}444 - 0{,}15$), тяга висіння ($0{,}444$) або більше тяги ($0{,}444 + 0{,}15$). PPO наприкінці керує тягою плавно. Щоб порівнювати методи чесно, домовимося про протокол.

- **Крок взаємодії** — один виклик середовища, 0,02 с польоту. Навчання міряють кроками, а не епізодами: епізоди бувають різної довжини.
- **Тестові старти** — 20 окремих початкових станів, згенерованих із зерен 1000–1019. Політику перевіряють на них без випадкових дій, і під час навчання вона цих стартів не бачить.
- **Нормована віддача** — сума винагород епізоду, поділена на його тривалість у секундах. Ідеальне висіння дає $+5{,}0$ за секунду; від'ємні значення означають, що апарат далеко від метра або падає.
- **Тривалість епізоду** — 8 с, якщо апарат протримався до кінця, менше — якщо впав або відлетів.
- **Зерно** (*random seed*) — початкове число генератора випадковості. Від нього залежать початкові ваги мережі, стартові стани й випадкові дії, тож прогони з різними зернами дають різні криві навіть за однакового алгоритму. Кожен алгоритм ми запускаємо на п'яти зернах і наводимо **середнє ± розкид** — середнє значення й стандартне відхилення між зернами.

Для орієнтиру — три політики без навчання. Ручне правило дає більше тяги, коли апарат нижче цілі з урахуванням швидкості ($z - 1 + 0{,}5\,v_z < 0$), і менше — інакше. Його результат +3,33 за секунду — планка, яку навчена політика має перевищити.


*Продовження блоку «Середовище висіння: один крок фізики й винагороди без округлень»: цей код виконується разом із ним.*

<CodeFold title="Три рівні тяги, тестові старти й три прості політики для порівняння" :lines="30" sec="0.1">

```python
# продовження блоку «Середовище висіння»
U_HOVER = M * G / T_MAX  # тяга, за якої сила тяги дорівнює вазі
ACTIONS = U_HOVER + np.array([-0.15, 0.0, 0.15])  # менше тяги / висіти / більше тяги
TEST_SEEDS = range(1000, 1020)  # ті самі тестові старти, що й для PPO наприкінці


def evaluate(policy):
    """Нормована віддача (за секунду) і тривалість на тестових стартах."""
    res = []
    for seed in TEST_SEEDS:
        env, total, n, done = Hover1D(), 0.0, 0, False
        obs = env.reset(np.random.default_rng(seed))
        while not done:  # policy(obs) — номер дії 0, 1 або 2
            obs, r, crashed, timeout, _ = env.step(ACTIONS[policy(obs)])
            total, n, done = total + r, n + 1, crashed or timeout
        res.append((total / (n * DT), n * DT))
    return np.mean(res, axis=0)


rng = np.random.default_rng(0)
BASELINES = {
    "випадкова дія": lambda obs: rng.integers(3),
    "завжди «висіти»": lambda obs: 1,
    "ручне правило": lambda obs: 2 if obs[0] + 0.5 * obs[1] < 0 else 0,
}
print("тяга трьох дій:", "  ".join(f"{u:.3f}" for u in ACTIONS))
print("політика            віддача за с   епізод, с")
for name, policy in BASELINES.items():
    ret, dur = evaluate(policy)
    print(f"{name:18s} {ret:+12.2f} {dur:11.1f}")
```

## Частина 1 · Від таблиці до нейромережі

Табличні методи модуля 04 працюють, поки станів кілька десятків. Стан дрона неперервний: кожне його значення — новий рядок таблиці. Потрібна функція, яка видає оцінку і для стану, якого агент ще не бачив.

### Як виглядала таблиця

Почнемо з того, що було в модулі 04. Q-learning на сітці три на три зберігав таблицю: рядок — стан, стовпець — дія, у комірці — оцінка цінності дії. Ліворуч саме ця таблиця після 400 епізодів, ті самі числа, що друкував код модуля 04.


<Figure src="/figs/own/m05e-qtable.png" alt="Q-таблиця сітки 3×3 з модуля 04: рядок — стан, стовпець — дія; поруч мережа, що дає те саме відображення формулою">

Q-таблиця сітки 3×3 з модуля 04: рядок — стан, стовпець — дія; поруч мережа, що дає те саме відображення формулою

</Figure>


Щоб обрати дію, агент знаходить рядок свого стану й бере стовпець із найбільшим числом: у стані (1,2) це «праворуч», 10,00. Таблиця — це просто відображення «стан → чотири числа», записане поштучно.

Праворуч те саме відображення записане формулою: на вході два числа, що описують стан, на виході — чотири оцінки, по одній на дію. Між ними — шари нейронів із вагами $\theta$. Навчати мережу — означає підбирати $\theta$ так, щоб її виходи збігалися з тими числами, які раніше стояли б у таблиці. Різниця в тому, що таблиця нічого не знає про стан, якого в ній немає, а формула дає відповідь для будь-якого входу.

### Таблиця для дрона

Спробуймо таблицю на задачі висіння. Стан неперервний, тож його доводиться нарізати: 20 рівнів похибки висоти від −1 до 1 м і 20 рівнів швидкості від −2 до 2 м/с — 400 рядків по 3 дії, 1 200 чисел. Код — той самий Q-learning, що в модулі 04, лише номер рядка тепер рахує функція `cell`.


*Продовження блоку «Три рівні тяги, тестові старти й три прості політики для порівняння»: цей код виконується разом із ним.*

<CodeFold title="Таблиця Q для дрона: 20 × 20 рядків, 5 зерен по 102 тис. кроків" :lines="41" sec="17.1">

```python
# продовження блоку «Три рівні тяги»
BINS = 20  # 20 рівнів похибки висоти × 20 рівнів швидкості = 400 рядків таблиці
TOTAL, EVAL_EVERY = 102_400, 5_120  # кроків навчання; оцінка кожні 5 120 кроків


def cell(obs):
    """Номер рядка таблиці: похибка висоти в [-1, 1] м, v_z у [-2, 2] м/с."""
    i = np.clip(((obs[0] + 1) / 2 * BINS).astype(int), 0, BINS - 1)
    j = np.clip(((obs[1] + 2) / 4 * BINS).astype(int), 0, BINS - 1)
    return i, j


def q_table(seed, alpha=0.1, gamma=0.99):
    rng = np.random.default_rng(seed)
    Q, visits = np.zeros((BINS, BINS, 3)), np.zeros((BINS, BINS), int)
    env, curve = Hover1D(), []
    obs = env.reset(rng)
    for t in range(1, TOTAL + 1):
        s = cell(obs)
        eps = max(0.05, 1 - t / 10_000)  # ε спадає від 1 до 0,05 за 10 тис. кроків
        a = rng.integers(3) if rng.random() < eps else int(Q[s].argmax())
        obs2, r, crashed, timeout, _ = env.step(ACTIONS[a])
        target = r + (0.0 if crashed else gamma * Q[cell(obs2)].max())
        Q[s][a] += alpha * (target - Q[s][a])  # те саме правило, що в модулі 04
        visits[s] += 1
        obs = env.reset(rng) if crashed or timeout else obs2
        if t % EVAL_EVERY == 0:
            curve.append(evaluate(lambda o: int(Q[cell(o)].argmax())))
    return np.array(curve), Q, visits


runs = [q_table(seed) for seed in range(5)]
curves = np.array([c for c, _, _ in runs])
np.savez("m05_table.npz", curves=curves, Q=runs[0][1], visits=runs[0][2])
print("кроки, тис.   віддача за с, середнє ± розкид   епізод, с")
for k in (0, 1, 3, 9, 19):
    r, d = curves[:, k, 0], curves[:, k, 1]
    row = f"{r.mean():+16.2f} ± {r.std():5.2f} {d.mean():11.1f}"
    print(f"{(k + 1) * EVAL_EVERY / 1000:11.1f} {row}")
never = [(v == 0).mean() for _, _, v in runs]
print(f"рядків таблиці, де агент не був жодного разу: {np.mean(never):.0%}")
```

### Мережа замість таблиці

Мережа цінності дій отримує на вхід стан і видає оцінки для всіх дій одразу. Її параметри $\theta$ — ваги й зсуви нейронів.


<Figure src="/figs/ext/m05d-q-network.png" alt="Нейромережа цінності дій: стан на вході, по одній оцінці Q на кожну дію на виході">

Джерело: [Albrecht, Christianos, Schäfer, *Multi-Agent Reinforcement Learning*, MIT Press, 2024](https://www.marl-book.com/), рис. 8.1. Стан $s$ подається на вхід, прихованих шарів два, на виході — по одному числу $Q(s, a_1;\theta), \dots, Q(s, a_{|A|};\theta)$ для кожної дії.

</Figure>


Для висіння мережа має 2 входи, два шари по 64 нейрони і 3 виходи. Код рахує її розмір. Для двох змінних мережа навіть більша за таблицю — 4 547 параметрів проти 1 200 комірок. Але з дванадцятьма змінними таблиця зростає до $10^{16}$ комірок, а мережа — лише до 5 187 параметрів. Головне ж інше: мережа **узагальнює** — схожі стани отримують схожі оцінки, тож досвід в одному стані підказує й сусіднім.

Один прямий прохід дає цінності всіх дій — зручно для вибору $\arg\max$. Звідси й обмеження: така архітектура працює лише зі скінченним набором дій, тому DQN керує трьома рівнями тяги, а не плавною тягою.


*Продовження блоку «Три рівні тяги, тестові старти й три прості політики для порівняння»: цей код виконується разом із ним.*

<CodeFold title="Мережа замість таблиці: 2 → 64 → 64 → 3 і скільки в ній параметрів" :lines="30" sec="0.9">

```python
# продовження блоку «Три рівні тяги»
import torch
from torch import nn

torch.set_num_threads(1)


def mlp(n_out, n_in=2):
    """Мережа n_in → 64 → 64 → n_out; на вході похибка висоти й v_z."""
    return nn.Sequential(
        nn.Linear(n_in, 64),
        nn.ReLU(),
        nn.Linear(64, 64),
        nn.ReLU(),
        nn.Linear(64, n_out),
    )


def size(net):
    return sum(p.numel() for p in net.parameters())


torch.manual_seed(0)
q = mlp(3)  # ще не навчена: ваги випадкові
obs = torch.tensor([-0.13, -0.12])  # на 13 см нижче цілі й опускається
with torch.no_grad():
    print("Q(s, ·) для трьох дій:", "  ".join(f"{v:+.3f}" for v in q(obs)))
print("змінних стану   комірок таблиці (20 рівнів)   параметрів мережі")
for n in (2, 12):
    print(f"{n:9d} {3 * 20**n:31.3g} {size(mlp(3, n)):19d}")
```

## Частина 2 · DQN

Найпростіша ідея — взяти Q-learning з модуля 04 і замінити таблицю мережею. DQN (*Deep Q-Network*) змусив цю ідею працювати на іграх Atari двома механізмами. Спершу подивимося, що ламається без них, потім — чому, а тоді розберемо кожен механізм окремо.

### Наївна ідея: Q-learning із мережею

У модулі 04 оновлення зсувало комірку таблиці до цілі. Для мережі те саме записують як втрату: квадрат різниці між оцінкою мережі та ціллю, яку рахує та сама мережа.

$$L(\theta) = \Big(\underbrace{r + \gamma \max_{a'} Q(s',a';\theta)}_{\text{ціль}} - Q(s,a;\theta)\Big)^2$$

Тут $(s,a,r,s')$ — один перехід, $\gamma$ — коефіцієнт дисконтування, $\theta$ — ваги мережі. Крок градієнтного спуску за $\theta$ зменшує цю різницю. На практиці таке пряме перенесення розходиться, і причин дві. Обидві видно на справжній мережі задачі висіння — наступні дві картки.

1. **Рухома ціль**: ціль рахує та сама мережа, яку ми змінюємо.
2. **Корельовані вибірки**: сусідні кроки одного польоту майже однакові.

### Проблема 1: ціль рухається разом з оцінкою

У таблиці оновлення змінює одну комірку. У мережі всі оцінки залежать від тих самих ваг, тож крок заради одного стану зсуває оцінки й інших станів — зокрема наступного стану $s'$, з якого рахується ціль.


<Figure src="/figs/own/m05e-moving-net.png" alt="Один крок градієнта справжньої мережі DQN змінив оцінки в усіх сусідніх станах і зсунув ціль">

Один крок градієнта справжньої мережі DQN змінив оцінки в усіх сусідніх станах і зсунув ціль

</Figure>


Рисунок — справжня мережа DQN на кроці 5 000 і один перехід із міні-пакета. Ми зробили один крок градієнта, що підняв $Q(s, \text{«менше тяги»})$ майже на одиницю. Ліворуч — що змінилося б у таблиці: одна комірка. Праворуч — що змінилося в мережі: оцінки цієї дії сильно піднялися в усіх станах, де апарат нижче цілі, і трохи — майже всюди. Наступний стан $s'$ лежить поруч із $s$, тож його оцінка теж зросла, а з нею й ціль. Наступного разу оновлення поженеться за новою, вищою ціллю — агент женеться за власною тінню.

### Проблема 2: сусідні кроки майже однакові

Досвід надходить послідовно: крок за кроком того самого польоту. За 0,02 с апарат майже не рухається, тож сусідні переходи майже однакові. Якщо навчати мережу на останніх кроках, кожен пакет складатиметься з одного й того самого стану.


<Figure src="/figs/own/m05e-correlated.png" alt="Останні 64 кроки підряд лежать в одній точці, а 64 випадкові переходи з буфера покривають усю область">

Останні 64 кроки підряд лежать в одній точці, а 64 випадкові переходи з буфера покривають усю область

</Figure>


Ліворуч — останні 64 кроки DQN на кроці навчання 20 000: усі вони лежать в одній точці біля цілі. Мережа, яку довго вчать на таких пакетах, підганяє оцінки під цю точку й забуває інші стани — це **катастрофічне забування**. Праворуч — 64 переходи, вибрані з усієї пам'яті навмання: вони з різних польотів і різних етапів навчання й покривають усю область, де бував агент.

### Смертельна тріада: три складники

Обидві проблеми — прояви загальнішого явища. Sutton і Barto назвали його **смертельною тріадою** (*deadly triad*): навчання може розійтися, коли разом присутні три речі. Розберемо кожну окремо, на простих прикладах.

**1. Апроксимація функції.** Оцінки не зберігаються поштучно, а обчислюються зі спільних параметрів. Приклад із життя: рекомендаційна система, що переоцінила один фільм, разом із ним змінює оцінки всіх схожих фільмів. У DQN це мережа: крок заради одного стану зсуває оцінки сусідніх, як на попередній картці.

**2. Бутстреп.** Ціль оновлення містить власну оцінку замість справжнього результату. Приклад: прогноз погоди на завтра уточнюють не за фактом, а за прогнозом на післязавтра. Якщо прогнози систематично завищені, помилка передається далі, а не виправляється. У DQN це ціль $r + \gamma \max Q(s')$.

**3. Навчання off-policy.** Оновлення йдуть не за тим розподілом станів, у якому діє політика, що її оцінюють. Приклад: учитися водити, переглядаючи записи чужих поїздок, — частину ситуацій, у які потрапите ви, там не показано. У DQN це навчання жадібної політики на досвіді ε-жадібної, зокрема старому, з буфера.

| **Складник** | **У DQN** | **Що буде без нього** |
|---|---|---|
| апроксимація | мережа $Q(s,a;\theta)$ | таблиця: не масштабується на дрон |
| бутстреп | ціль $r + \gamma \max_{a'} Q(s',a')$ | ціль — повна віддача епізоду: повільно й шумно |
| off-policy | досвід із буфера, ε-жадібні дії | лише свіжий досвід поточної політики |

Якщо присутні будь-які два складники, нестабільності можна уникнути. Небезпечні всі три одразу — і DQN має всі три. Він не прибирає жодного, а лише послаблює їхню взаємодію двома механізмами далі (Sutton, Barto, 2018, розд. 11.3; Albrecht et al., розд. 8.1).

### Тріада на числах: w → 2w

Найменший приклад розходження — із розд. 11.2 підручника Sutton і Barto. Два стани: A з ознакою 1 і B з ознакою 2. Лінійна апроксимація з одним параметром $w$ дає $V(A) = w$, $V(B) = 2w$. Перехід A → B приносить винагороду 0, з B епізод закінчується теж із нулем, тож справжні цінності обох станів — нуль. Починаємо з $w = 10$; $\gamma = 0{,}9$, $\alpha = 0{,}1$.

Оновлення переходу A → B за TD:

$$w \leftarrow w + \alpha\,\big(0 + \gamma \cdot 2w - w\big)\cdot 1 = \big(1 + \alpha(2\gamma - 1)\big)\,w = 1{,}08\,w$$

Ціль $\gamma \cdot 2w = 18$ більша за поточну оцінку $10$, тож $w$ росте. Але разом із $w$ росте й $V(B) = 2w$, а отже й ціль. Кожне оновлення множить $w$ на 1,08 — це і є рухома ціль у чистому вигляді. Множник більший за одиницю, коли $\gamma > 0{,}5$.


<CodeFold title="Тріада на числах: оцінка V(A) у прикладі w → 2w для чотирьох варіантів" :lines="25" sec="0.0">

```python
GAMMA, ALPHA, W0 = 0.9, 0.1, 10.0  # приклад Sutton, Barto, 2018, розд. 11.2
SHOW = (0, 10, 20, 50, 100)  # після скількох оновлень друкувати оцінку


def run(variant, n=100):
    """Оцінка V(A) після кожного оновлення. Ознаки станів A і B — 1 і 2."""
    w, v_b, path = W0, 2 * W0, [W0]  # v_b — окреме число для B (лише в таблиці)
    for _ in range(n):
        if variant == "без апроксимації":  # таблиця: у B власне значення
            w += ALPHA * (GAMMA * v_b - w)
        elif variant == "без бутстрепу":  # ціль — справжня віддача з A, вона 0
            w += ALPHA * (0.0 - w) * 1
        else:  # ціль 0 + γ·V(B) = γ·2w; похідна V(A) = 1·w за w дорівнює 1
            w += ALPHA * (GAMMA * 2 * w - w) * 1
            if variant == "без off-policy":  # оновлюємо й перехід B → кінець
                w += ALPHA * (0.0 - 2 * w) * 2  # похідна V(B) = 2w за w дорівнює 2
        path.append(w)
    return path


print("варіант               V(A) після стількох оновлень:")
print(" " * 20 + "".join(f"{k:>10d}" for k in SHOW))
for variant in ("усі три", "без off-policy", "без бутстрепу", "без апроксимації"):
    path = run(variant)
    print(f"{variant:20s}" + "".join(f"{path[k]:10.2f}" for k in SHOW))
```

### Replay buffer: пам'ять переходів

Перший механізм DQN — **буфер повторів** (*replay buffer*). Це черга фіксованої місткості. Кожен перехід $(s, a, r, s', \text{кінець})$ одразу після кроку дописують у кінець черги. Коли черга заповнена, найстаріший перехід витісняється. Навчання йде не на останньому переході, а на **міні-пакеті** — випадковій вибірці з усього буфера.


<Figure src="/figs/own/m05e-buffer.png" alt="Справжній буфер повторів DQN на кроці 20 000: окремі польоти, 64 випадкові номери для міні-пакета і кілька записів">

Справжній буфер повторів DQN на кроці 20 000: окремі польоти, 64 випадкові номери для міні-пакета і кілька записів

</Figure>


Угорі — справжній буфер DQN на кроці 20 000: 20 000 переходів, смуги — окремі польоти, помаранчеві риски — 64 номери для міні-пакета. Внизу — кілька рядків цього буфера. Так виглядає один запис пам'яті: два числа стану, номер дії, винагорода, два числа наступного стану й ознака кінця.

У нашому DQN буфер вміщає 50 000 переходів, а пакет має 64. Буфер лікує дві речі:

- **кореляцію**: у пакеті переходи з різних польотів, а не 64 майже однакові кроки;
- **марнування досвіду**: кожен перехід потрапляє в пакети багато разів — за 100 тис. кроків навчання DQN робить 101 тис. оновлень по 64 переходи, тобто кожен перехід потрапив у пакети в середньому близько 60 разів.

Плата — off-policy: у буфері лежать дії старих версій політики. Для Q-learning це прийнятно, бо його ціль не залежить від того, хто зробив дію. Для градієнта політики в частині 3 — ні.

### Target network: заморожена копія мережі

Другий механізм — **target network**, заморожена копія мережі з вагами $\bar\theta$. Мереж тепер дві:

- **основна мережа** $\theta$ обирає дії й навчається на кожному кроці;
- **target network** $\bar\theta$ лише рахує цілі $y = r + \gamma \max_{a'} Q(s',a';\bar\theta)$ і не навчається. Раз на $C$ кроків її ваги просто копіюють з основної: $\bar\theta \leftarrow \theta$.

Між копіюваннями ціль стоїть на місці, і основна мережа має час до неї наблизитися. Градієнт через ціль не пропускають: $\bar\theta$ у формулі вважається сталою.


<Figure src="/figs/own/m05e-staircase.png" alt="Оцінка того самого стану в основній мережі змінюється щокроку, а в target network — сходинками кожні 500 кроків">

Оцінка того самого стану в основній мережі змінюється щокроку, а в target network — сходинками кожні 500 кроків

</Figure>


Рисунок — справжній прогін DQN: оцінка того самого стану $s = (-0{,}13;\ -0{,}12)$ у двох мережах. Синя лінія — основна мережа, вона змінюється з кожним кроком. Помаранчеві сходинки — target network: вона стоїть 500 кроків, а тоді стрибком переймає ваги основної. Саме за цими сходинками й рахуються цілі.

Порядок у кожному кроці навчання такий: зробити дію, дописати перехід у буфер, узяти випадковий пакет, порахувати цілі за $\bar\theta$, зробити крок градієнта за $\theta$ і, якщо номер кроку ділиться на $C$, скопіювати $\theta$ у $\bar\theta$.

### Повний алгоритм DQN

Ось обидва механізми разом. Для задачі висіння: $\gamma = 0{,}99$, буфер на 50 000 переходів, пакет 64, копіювання кожні $C = 500$ кроків, $\epsilon$ спадає від 1 до 0,05 за перші 10 000 кроків.

1. Спостерегти стан $s$. З імовірністю $\epsilon$ обрати випадкову дію, інакше $a = \arg\max_a Q(s,a;\theta)$.
2. Зробити дію, отримати $r$ і $s'$; дописати $(s, a, r, s', \text{кінець})$ у буфер.
3. Узяти з буфера випадковий міні-пакет $B$.
4. Для кожного переходу пакета порахувати ціль за target network.
5. Зробити крок градієнта, що зменшує втрату $L(\theta)$.
6. Якщо номер кроку ділиться на $C$, скопіювати $\bar\theta \leftarrow \theta$. Повернутися до п. 1.

$$y = r + \gamma \max_{a'} Q(s',a';\bar\theta), \qquad L(\theta) = \frac{1}{|B|}\sum_{(s,a,r,s') \in B} \big(y - Q(s,a;\theta)\big)^2$$

| **Позначення** | **Значення** |
|---|---|
| $\theta$, $\bar\theta$ | ваги основної мережі та *target network* |
| $B$, $\lvert B \rvert$ | міні-пакет переходів із *replay buffer* і кількість переходів у ньому |
| $y$ | ціль оновлення; для переходу, що закінчився аварією, дорівнює просто $r$ |
| $L(\theta)$ | середньоквадратична втрата, яку мінімізують градієнтним спуском за $\theta$ |

Оригінальна робота: [Mnih та ін., *Human-level control through deep reinforcement learning*, Nature 2015](https://doi.org/10.1038/nature14236).

```python
# продовження блоку «Мережа замість таблиці»
import collections

TOTAL, EVAL_EVERY, SYNC = 102_400, 5_120, 500  # SYNC — період копіювання θ̄ ← θ


def dqn(seed, sync=SYNC, gamma=0.99, batch=64):
    rng = np.random.default_rng(seed)
    torch.manual_seed(seed)
    q, q_target = mlp(3), mlp(3)  # основна мережа θ і target network θ̄
    q_target.load_state_dict(q.state_dict())
    opt = torch.optim.Adam(q.parameters(), lr=1e-3)
    buffer = collections.deque(maxlen=50_000)  # найстаріші переходи витісняються
    env, curve = Hover1D(), []
    obs = env.reset(rng)
    for t in range(1, TOTAL + 1):
        eps = max(0.05, 1 - t / 10_000)
        with torch.no_grad():
            greedy = int(q(torch.as_tensor(obs)).argmax())
        a = rng.integers(3) if rng.random() < eps else greedy  # ε-жадібний вибір
        obs2, r, crashed, timeout, _ = env.step(ACTIONS[a])
        buffer.append((obs, a, r, obs2, crashed))  # 1. перехід — у буфер
        obs = env.reset(rng) if crashed or timeout else obs2
        if len(buffer) >= 1_000:  # 2. випадковий міні-пакет з усього буфера
            batch_idx = rng.integers(len(buffer), size=batch)
            rows = zip(*(buffer[i] for i in batch_idx), strict=True)
            s, a_, r_, s2, done = (torch.as_tensor(np.array(x)) for x in rows)
            with torch.no_grad():  # 3. ціль y рахує target network
                best_next = q_target(s2).max(1).values
                y = r_.float() + gamma * (1 - done.float()) * best_next
            pred = q(s).gather(1, a_.view(-1, 1)).squeeze(1)
            loss = ((y - pred) ** 2).mean()  # 4. крок градієнта лише по θ
            opt.zero_grad()
            loss.backward()
            opt.step()
        if t % sync == 0:  # 5. копіювання θ̄ ← θ
            q_target.load_state_dict(q.state_dict())
        if t % EVAL_EVERY == 0:
            with torch.no_grad():
                curve.append(evaluate(lambda o: int(q(torch.as_tensor(o)).argmax())))
    return np.array(curve), q


runs = {"з θ̄": [dqn(s) for s in range(5)], "без θ̄": [dqn(s, sync=1) for s in range(5)]}
curves = {k: np.array([c for c, _ in v]) for k, v in runs.items()}
np.savez("m05_dqn.npz", target=curves["з θ̄"], no_target=curves["без θ̄"])
torch.save(runs["з θ̄"][0][1].state_dict(), "m05_dqn_q.pt")
print("віддача за с, середнє ± розкид по 5 зернах")
print("кроки, тис.     з target network    без неї (θ̄ = θ)")
for k in (0, 1, 3, 9, 19):
    cols = [
        f"{c[:, k, 0].mean():+8.2f} ± {c[:, k, 0].std():4.2f}" for c in curves.values()
    ]
    print(f"{(k + 1) * EVAL_EVERY / 1000:11.1f}   {cols[0]:>17s}   {cols[1]:>17s}")
for name, c in curves.items():
    print(f"{name}: найгірша оцінка після 20 тис. кроків {c[:, 4:, 0].min():+.2f}")
```

## Частина 3 · Градієнт політики

DQN обирає дію як $\arg\max$ по виходах мережі, тому працює лише з кількома дискретними діями. Тяга дрона — неперервне число. Другий шлях обходить цінності дій: мережа видає саму політику, і її ваги зсувають так, щоб удалі дії ставали ймовірнішими.

### Навіщо вчити політику напряму

Політику задають мережею з вагами $\phi$: на вході стан, на виході — розподіл дій $\pi(a\mid s;\phi)$. Для наших трьох рівнів тяги це три ймовірності; для неперервної тяги — наприклад, середнє й розкид нормального розподілу, і тоді $\pi(a\mid s;\phi)$ — щільність, а не ймовірність, але формули нижче від цього не змінюються. Дію не обирають за максимумом, а **жеребкують** за цими ймовірностями — так політика сама досліджує, без $\epsilon$.


<Figure src="/figs/own/m05e-pg-loop.png" alt="Цикл REINFORCE: політика жеребкує дії, після епізоду рахуємо віддачі й робимо вдалі дії ймовірнішими">

Цикл REINFORCE: політика жеребкує дії, після епізоду рахуємо віддачі й робимо вдалі дії ймовірнішими

</Figure>


Мета — знайти $\phi$ з найбільшою очікуваною віддачею $J(\phi)$. Напрям, у якому $J$ зростає, дає **теорема про градієнт політики** (*policy gradient theorem*): диференціювати динаміку середовища не треба, досить знати, як політика змінює ймовірність власних дій (Sutton, Barto, розд. 13.2).

$$\nabla_\phi J(\phi) \propto \mathbb{E}_{s,\,a \sim \pi}\big[\, Q^\pi(s,a)\, \nabla_\phi \log \pi(a\mid s;\phi)\,\big]$$

| **Позначення** | **Значення** |
|---|---|
| $s, a \sim \pi$ | стани, які відвідує політика (з дисконтуванням), і дії, які вона в них обирає |
| $\pi(a\mid s;\phi)$ | імовірність дії $a$ у стані $s$ за поточних ваг (для неперервних дій — щільність) |
| $\nabla_\phi \log \pi(a\mid s;\phi)$ | напрям у просторі ваг, що робить дію $a$ ймовірнішою |
| $Q^\pi(s,a)$ | наскільки дія виявилася доброю: вага цього напряму |
| $\propto$ | «пропорційно»: сталий множник опущено, на напрям кроку він не впливає |

Ідея проста: збільшуй імовірність дій, які виявилися добрими, пропорційно тому, наскільки вони добрі. Найпростіша реалізація — **REINFORCE**: замість невідомої $Q^\pi(s_t,a_t)$ вона бере віддачу $G_t$ — дисконтовану суму винагород від кроку $t$ до кінця епізоду. Така оцінка незміщена, але дуже шумна.

### Віддача від кожного кроку

REINFORCE чекає кінця епізоду, а тоді для кожного кроку рахує віддачу $G_t$ — суму всіх наступних винагород із дисконтом. Рахувати зручно з кінця: віддача останнього кроку — його винагорода, а кожна попередня — власна винагорода плюс дисконтована віддача наступного кроку.

$$G_t = r_t + \gamma\, G_{t+1}, \qquad G_T = r_T$$

Перші півтори секунди апарат біля цілі, і винагороди додатні, далі він відлітає, винагороди стають дедалі гіршими, і на 3,12 с епізод обривається аварією. Для REINFORCE це означає: дії на початку епізоду отримають від'ємний сигнал за аварію, у якій вони, можливо, не винні. Звідси шум, про який ітиметься далі.

### REINFORCE на числах

Один крок REINFORCE для однієї дії. Три дії, спершу рівноймовірні. Агент спробував дію 1 (нумерація з нуля) на першому кроці, і віддача від цього кроку $G = +2$ або $G = -2$. Політику задамо найпростіше: три числа-**логіти** $z$, з яких функція **softmax** робить імовірності $\pi_i = e^{z_i} / \sum_j e^{z_j}$. Градієнт логарифма ймовірності спробуваної дії $a$ за логітами $\nabla_z \log \pi_a = e_a - \pi$ — одиниця на місці спробуваної дії мінус поточні ймовірності. У нейромережі логіти видає мережа, і далі градієнт іде до ваг $\phi$ за правилом ланцюга.


<CodeFold title="Один крок REINFORCE: як віддача від кроку змінює ймовірність спробуваної дії" :lines="15" sec="0.1">

```python
import numpy as np


def softmax(z):
    e = np.exp(z - z.max())
    return e / e.sum()


LR, a = 0.5, 1  # темп навчання; агент спробував дію 1 із трьох
logits = np.zeros(3)  # на старті всі три дії рівноймовірні
pi_old = softmax(logits)
for G in (+2.0, -2.0):  # віддача від кроку, на якому зроблено дію 1
    grad = G * (np.eye(3)[a] - pi_old)  # G × ∇_z log π(a) для softmax
    pi_new = softmax(logits + LR * grad)
    print(f"віддача G = {G:+.0f}: π(дія 1) {pi_old[a]:.3f} → {pi_new[a]:.3f}")
```

### Алгоритм REINFORCE по кроках

Повний алгоритм — це той самий крок, повторений для всіх кроків епізоду:

1. Пролетіти цілий епізод поточною політикою: у кожному стані жеребкувати дію за $\pi(\cdot\mid s;\phi)$ і запам'ятовувати $s_t$, $a_t$, $r_t$.
2. Коли епізод закінчився, порахувати з кінця віддачу $G_t$ для кожного кроку.
3. Скласти втрату $L(\phi) = -\frac{1}{T}\sum_t G_t \log \pi(a_t \mid s_t;\phi)$: мінус — бо втрату мінімізують, а віддачу хочемо збільшити.
4. Зробити один крок градієнта за $\phi$. Старий епізод викинути й пролетіти новий уже новою політикою.

Код нижче — ці чотири кроки на задачі висіння з тією самою мережею 2 → 64 → 64 → 3, лише її виходи тепер — логіти, а не оцінки Q.

```python
# продовження блоку «Мережа замість таблиці»
TOTAL, EVAL_EVERY, GAMMA_RL = 204_800, 10_240, 0.99


def sample(pi, obs, rng):
    """Дія з розподілу політики: softmax над трьома логітами."""
    with torch.no_grad():
        p = torch.softmax(pi(torch.as_tensor(obs)), -1).numpy().astype(float)
    return rng.choice(3, p=p / p.sum())


def greedy(pi):
    return lambda o: int(pi(torch.as_tensor(o)).argmax())


def reinforce(seed, lr=1e-3):
    rng = np.random.default_rng(seed)
    torch.manual_seed(seed)
    pi = mlp(3)  # політика φ: стан → логіти трьох дій
    opt = torch.optim.Adam(pi.parameters(), lr=lr)
    env, t, curve = Hover1D(), 0, []
    while t < TOTAL:
        obs, done, S, A, R = env.reset(rng), False, [], [], []
        while not done:  # 1. цілий епізод поточною політикою
            a = sample(pi, obs, rng)
            obs2, r, crashed, timeout, _ = env.step(ACTIONS[a])
            S, A, R = S + [obs], A + [a], R + [r]
            obs, done, t = obs2, crashed or timeout, t + 1
            if t % EVAL_EVERY == 0:
                with torch.no_grad():
                    curve.append(evaluate(greedy(pi)))
        G = np.zeros(len(R))
        for k in reversed(range(len(R))):  # 2. віддача G_t від кожного кроку, з кінця
            G[k] = R[k] + GAMMA_RL * (G[k + 1] if k + 1 < len(R) else 0.0)
        logp = torch.log_softmax(pi(torch.as_tensor(np.array(S))), -1)
        logp = logp[torch.arange(len(A)), torch.as_tensor(np.array(A))]
        loss = -(torch.as_tensor(G, dtype=torch.float32) * logp).mean()  # 3. G·log π
        opt.zero_grad()
        loss.backward()
        opt.step()  # 4. крок градієнта по φ
    return np.array(curve)


curves = np.array([reinforce(seed) for seed in range(5)])
```

## Частина 4 · Актор–критик

Віддача епізоду — дуже шумний сигнал: вона залежить від усіх наступних випадкових дій і переходів, а не лише від оцінюваної. Щоб навчання не хиталося, до політики додають другу мережу, яка оцінює стани, і порівнюють результат дії з тим, чого в цьому стані зазвичай очікують.

### Перевага замість віддачі

Нехай у якомусь стані три дії дають віддачі 9, 10 і 11. Кожне окреме оновлення REINFORCE робить спробувану дію ймовірнішою — навіть найгіршу, бо її $G = 9$ теж додатне. У середньому за багато епізодів краща дія все одно виграє, але окремі кроки смикають політику в різні боки: це і є шум. Якщо відняти те, що в цьому стані й так очікують, — 10, — сигнали стануть −1, 0 і +1, і вже окремий крок штовхає гіршу дію вниз, а кращу вгору. Середній напрям при цьому не змінюється: базова лінія, яка не залежить від дії, зберігає очікуваний градієнт і зменшує лише його розкид.

Це й робить **перевага** (*advantage*): на скільки дія краща за звичайну в цьому стані. Оцінку «звичайного» дає друга мережа — **критик** $V(s;\theta)$, де $\theta$ тепер — ваги критика; політику називають **актором**.

$$\mathrm{Adv}(s,a) = Q(s,a) - V(s) \approx r + \gamma V(s') - V(s)$$

Права частина — та сама часова різниця, що в модулі 04: винагорода кроку плюс оцінка наступного стану мінус оцінка поточного. Її можна порахувати після одного кроку, не чекаючи кінця епізоду.


<Figure src="/figs/own/m05d-actor-critic.png" alt="Схема актор–критик: актор обирає дію, критик оцінює стани, перевага оновлює актора">

Схема актор–критик: актор обирає дію, критик оцінює стани, перевага оновлює актора

</Figure>


У прикладі на схемі критик оцінює поточний стан у 0,9, наступний — у 3,0, винагорода 0,2: перевага $0{,}2 + 0{,}9 \cdot 3{,}0 - 0{,}9 = +2{,}0$. Підставте її замість $G = +2$ у код попередньої частини — і отримаєте ті самі 0,333 → 0,576: формула кроку та сама, змінилося лише джерело сигналу.

### Алгоритм A2C по кроках

Метод, що діє саме так, — **A2C** (*Advantage Actor-Critic*, Albrecht et al., розд. 8.2.5). Він не чекає кінця епізоду:

1. Зробити кілька кроків поточною політикою (у нас 5), жеребкуючи дії, і запам'ятати переходи.
2. Для кожного переходу порахувати ціль критика $y = r + \gamma V(s';\theta)$; після аварії $V(s') = 0$.
3. Порахувати перевагу $\mathrm{Adv} = y - V(s;\theta)$: наскільки результат дії кращий, ніж очікував критик.
4. Зробити один крок градієнта одразу для обох мереж: актор — у бік дій із додатною перевагою, критик — до цілі $y$. Повернутися до п. 1.

До цілі актора, яку максимізують, додають ще один доданок з малою вагою — **ентропію** розподілу дій, міру його невизначеності (у втраті, яку мінімізують, вона стоїть зі знаком мінус). Вона найбільша, коли всі дії рівноймовірні, і нульова, коли політика завжди обирає одну. Бонус за ентропію штрафує передчасну впевненість і так підтримує дослідження — роль, яку в DQN виконувало $\epsilon$.

Код — ці чотири кроки. Наприкінці він друкує одне справжнє оновлення зерна 0 на 40 тис. кроках.

```python
# продовження блоку «REINFORCE на задачі висіння»
N_STEPS, SHOW_AT = 5, 40_000  # оновлення кожні 5 кроків; приклад — оновлення на 40 тис.


def a2c(seed, lr=7e-4, ent_coef=0.01):
    rng = np.random.default_rng(seed)
    torch.manual_seed(seed)
    pi, critic = mlp(3), mlp(1)  # актор φ і критик θ, що оцінює V(s)
    params = [*pi.parameters(), *critic.parameters()]
    opt = torch.optim.Adam(params, lr=lr)
    env, curve, example = Hover1D(), [], None
    obs = env.reset(rng)
    for t in range(N_STEPS, TOTAL + 1, N_STEPS):
        batch = []
        for _ in range(N_STEPS):  # 1. п'ять кроків поточною політикою
            a = sample(pi, obs, rng)
            obs2, r, crashed, timeout, _ = env.step(ACTIONS[a])
            batch.append((obs, a, r, obs2, crashed))
            obs = env.reset(rng) if crashed or timeout else obs2
        s, act, r, s2, term = (
            torch.as_tensor(np.array(x)) for x in zip(*batch, strict=True)
        )
        with torch.no_grad():  # 2. ціль критика r + γ·V(s′); після аварії V(s′) = 0
            v_next = critic(s2).squeeze(1) * (1 - term.float())
            y = r.float() + GAMMA_RL * v_next
        v = critic(s).squeeze(1)
        adv = (y - v).detach()  # 3. перевага: наскільки дія краща, ніж чекав критик
        dist = torch.distributions.Categorical(logits=pi(s))
        loss = -(adv * dist.log_prob(act)).mean() + 0.5 * ((y - v) ** 2).mean()
        loss = loss - ent_coef * dist.entropy().mean()  # бонус за ентропію
        opt.zero_grad()
        loss.backward()  # 4. один крок по φ і θ разом
        torch.nn.utils.clip_grad_norm_(params, 0.5)
        opt.step()
        if seed == 0 and t == SHOW_AT:
            cols = (act, r, v, GAMMA_RL * v_next, adv)
            example = list(zip(*(c.tolist() for c in cols), strict=True))
        if t % EVAL_EVERY == 0:
            with torch.no_grad():
                curve.append(evaluate(greedy(pi)))
    return np.array(curve), example


runs = [a2c(seed) for seed in range(5)]
curves_a2c = np.array([c for c, _ in runs])
np.save("m05_a2c.npy", curves_a2c)
print(f"одне оновлення A2C, зерно 0, кроки {SHOW_AT - 4}–{SHOW_AT}:")
print("дія       r     V(s)   γ·V(s′)   перевага")
for a, r, v, gvn, adv in runs[0][1]:
    print(f"{a:3d} {r:+8.3f} {v:+8.2f} {gvn:+9.2f} {adv:+10.3f}")
print("кроки, тис.   A2C, середнє ± розкид   REINFORCE, середнє ± розкид")
for k in (0, 4, 9, 19):
    a, b = curves_a2c[:, k, 0], curves[:, k, 0]
    row = f"{a.mean():+12.2f} ± {a.std():4.2f} {b.mean():+16.2f} ± {b.std():4.2f}"
    print(f"{(k + 1) * 10.24:11.1f}{row}")
```

## Частина 5 · PPO

Навіть за малого темпу навчання один крок градієнта може змінити політику так сильно, що якість різко впаде, а зіпсована політика збиратиме вже непридатні дані. PPO (*Proximal Policy Optimization*) знімає стимул відводити політику далеко від тієї, що зібрала дані. Саме ним у частині 6 навчено політику висіння з плавною тягою.

### PPO: навіщо обмежувати крок

Нова політика порівнюється зі старою через відношення ймовірностей $\rho$: у скільки разів оновлення змінило ймовірність дії. Ціль PPO бере менше з двох чисел — звичайне $\rho\,\mathrm{Adv}$ і те саме з $\rho$, обрізаним до коридору $[1-\epsilon_{\text{clip}},\ 1+\epsilon_{\text{clip}}]$.

$$\rho = \frac{\pi(a\mid s;\phi)}{\pi_\beta(a\mid s)}, \qquad L(\phi) = -\min\Big(\rho\,\mathrm{Adv},\ \ \mathrm{clip}\big(\rho,\, 1-\epsilon_{\text{clip}},\, 1+\epsilon_{\text{clip}}\big)\,\mathrm{Adv}\Big)$$

| **Позначення** | **Значення** |
|---|---|
| $\pi(a\mid s;\phi)$, $\pi_\beta$ | нова політика з вагами $\phi$ і політика, яка зібрала дані (до оновлення) |
| $\mathrm{Adv}$ | перевага дії $a$ у стані $s$ |
| $\epsilon_{\text{clip}}$ | ширина коридору навколо 1; типово 0,2 |
| $L(\phi)$ | втрата одного переходу; мінус — бо втрату мінімізують, а ціль $\min(\dots)$ максимізують |


<Figure src="/figs/own/m04-ppo-clip.png" alt="Обрізана цільова функція PPO для переваги +2 і −2; точки — ті самі ρ і цілі, що в коді лекції">

Обрізана цільова функція PPO для переваги +2 і −2; точки — ті самі ρ і цілі, що в коді лекції

</Figure>


Якщо дія була вдалою, вигоду від подальшого підвищення її ймовірності перестають зараховувати, щойно $\rho$ перевищує $1+\epsilon_{\text{clip}}$. Якщо невдалою — так само не зараховують зниження ймовірності нижче $1-\epsilon_{\text{clip}}$, але штраф за те, що невдалу дію зробили ймовірнішою, не обмежують. Тому один пакет досвіду можна пройти кілька **епох** поспіль (епоха — один повний прохід по пакету) з меншим ризиком зіпсувати політику. Гарантії обрізання не дає: інші переходи пакета все одно зсувають спільні ваги. Стаття: [Schulman та ін., arXiv:1707.06347](https://arxiv.org/abs/1707.06347).

### PPO на числах: де обрізання зупиняє крок

Той самий крок політики, що й у REINFORCE, тепер із перевагою $\pm 2$, обрізанням PPO і типовим коридором $\epsilon_{\text{clip}} = 0{,}2$. Віджет нижче дає покрутити $\rho$, перевагу й ширину коридору.


*Продовження блоку «Один крок REINFORCE: як віддача від кроку змінює ймовірність спробуваної дії»: цей код виконується разом із ним.*

```python
for adv in (+2.0, -2.0):
```

### Алгоритм PPO по кроках

PPO — це актор–критик A2C з двома змінами: досвід збирають більшими порціями і проходять кожну порцію кілька разів, а обрізання не дає політиці відійти далеко. Значення — за замовчуванням у Stable-Baselines3, з ними навчено політику висіння.

1. Зібрати 2 048 кроків поточною політикою $\pi_\beta$, запам'ятавши для кожного кроку ймовірність обраної дії $\pi_\beta(a\mid s)$.
2. Порахувати переваги $\mathrm{Adv}$ і цілі критика. Stable-Baselines3 рахує перевагу не за один крок, як A2C, а змішуючи багато кроків уперед з вагою $\lambda = 0{,}95$ (GAE, докладно в модулі 07).
3. Десять разів пройти зібрані 2 048 кроків міні-пакетами по 64. Для кожного переходу порахувати $\rho = \pi(a\mid s;\phi) / \pi_\beta(a\mid s)$ і ціль з обрізанням $\epsilon_{\text{clip}} = 0{,}2$; зробити крок градієнта для актора, критика й ентропії.
4. Нова політика стає $\pi_\beta$; повернутися до п. 1.

На першому проході $\rho = 1$ для всіх переходів: політика ще не змінювалася. З кожним проходом вона віддаляється від $\pi_\beta$, і обрізання дедалі частіше вимикає внесок переходів, що вже відійшли за коридор.

У циклі нижче $K$ — кількість епох, тобто проходів по зібраному пакету.

### Що PPO вимірює на кожному оновленні

Stable-Baselines3 після кожного оновлення друкує кілька чисел. За ними видно, що відбувається з політикою, — це телеметрія навчання, як телеметрія польоту.


<Figure src="/figs/own/m05e-ppo-telemetry.png" alt="Телеметрія PPO на кожному оновленні: частка обрізань, KL, поясненна дисперсія і розкид тяги">

Телеметрія PPO на кожному оновленні: частка обрізань, KL, поясненна дисперсія і розкид тяги

</Figure>


Справжній прогін висіння, зерно 0, 149 оновлень:

- **частка обрізаних переходів** (*clip fraction*) зростає від кількох відсотків до чверті: що точніша політика, то частіше один прохід уже впирається в коридор;
- **KL-розбіжність** нової й старої політики лишається малою — кілька сотих, з рідкими сплесками до 0,13: обрізання тримає крок малим, але не жорстко;
- **поясненна дисперсія** (*explained variance*) показує, наскільки критик передбачає віддачі: у першій половині навчання вона стрибає від нуля й назад, після 150 тис. кроків — майже 1;
- **розкид тяги** $\sigma$ — стандартне відхилення гауссіана, з якого жеребкують дію: від 1 до 0,02. Політика перестає досліджувати й стає майже детермінованою.

Ці графіки — перше, на що дивляться, коли навчання не йде: обрізання не спрацьовує ніколи — крок надто малий; KL великий — крок надто великий; поясненна дисперсія нульова — критик нічого не вивчив.

```python
    observation_space = gym.spaces.Box(-np.inf, np.inf, (2,), np.float32)
    action_space = gym.spaces.Box(-1.0, 1.0, (1,), np.float32)

            self.rng = np.random.default_rng(seed)
        return self.core.reset(self.rng, self.z_range), {}

    def step(self, action):
        obs, r, crashed, timeout, _ = self.core.step((action[0] + 1) / 2)
        return obs, r, crashed, timeout, {}


def evaluate(model, z_range):
    """Нормована віддача (за секунду) і тривалість епізоду на тестових зернах."""
    res = []

        env, total, n, done = HoverGym(z_range), 0.0, 0, False
        obs, _ = env.reset(seed=s)
        while not done:
            action = model.predict(obs, deterministic=True)[0]
            obs, r, crashed, timeout, _ = env.step(action)
            total, n, done = total + r, n + 1, crashed or timeout
        res.append((total / (n * DT), n * DT))
    return np.mean(res, axis=0)


curves = np.zeros((len(STARTS), len(TRAIN_SEEDS), N_EVAL, 2))
for j, z_range in enumerate(STARTS.values()):
```

### Висновки

- Таблиця — це відображення «стан → оцінки дій», записане поштучно. Для дрона вона здебільшого порожня (64 % рядків навіть для двох змінних), а мережа те саме відображення записує формулою й узагальнює на сусідні стани.
- Наївне глибоке Q-навчання розходиться: крок для одного стану зсуває оцінки інших — і саму ціль; сусідні кроки майже однакові. Обидві проблеми — прояви смертельної тріади: апроксимація, бутстреп і off-policy разом. У прикладі w → 2w досить прибрати будь-який складник.
- DQN тріаду не прибирає, а послаблює: *replay buffer* дає випадкові пакети з усієї пам'яті, *target network* заморожує ціль на $C$ кроків. На висінні без target network три зерна з п'яти раз у раз обвалюються, з нею — ні, хоча окремі провали лишаються.
- Градієнт політики робить удалі дії ймовірнішими й працює з неперервними діями. REINFORCE бере сигнал із віддачі всього хвоста епізоду, тому шумний: +2,60 за секунду на висінні.
- Актор–критик порівнює результат дії з очікуванням критика й оновлюється кожні кілька кроків: A2C на тій самій мережі дав +4,09.
- PPO збирає досвід порціями, проходить кожну кілька разів і обрізанням не дає політиці відійти далеко. Його телеметрія — частка обрізань, KL, поясненна дисперсія, розкид дій — показує, що відбувається з навчанням.
- Висновок про алгоритм робиться лише за кількома зернами, на окремих тестових стартах і за однакового бюджету.
